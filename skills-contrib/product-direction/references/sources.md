# Sources

Every structural element of this skill names its source below: a project that relies on it. Where an element has no direct source, the table says so. Read on 2026-10-22.

Short names:

- **Kody**: [kody-hq/kody](https://github.com/kody-hq/kody), its [project intent](https://github.com/kody-hq/kody/blob/main/docs/contributing/project-intent.md), [decisions index](https://github.com/kody-hq/kody/blob/main/docs/contributing/decisions/index.md) and [record template](https://github.com/kody-hq/kody/blob/main/docs/contributing/decisions/0000-template.md).
- **Nygard**: Michael Nygard, [Documenting Architecture Decisions](https://cognitect.com/blog/2011/11/15/documenting-architecture-decisions), 2011.
- **Epic Stack**: [epicweb-dev/epic-stack `docs/decisions/`](https://github.com/epicweb-dev/epic-stack/tree/main/docs/decisions).
- **The Sweeper**: VS Code's issue review agent, its policy [`review-item.md`](https://github.com/egamma/vscodesweeper-state/blob/main/policy/microsoft/vscode/review-item.md).
- **VS Code**: the [Roadmap](https://github.com/microsoft/vscode/wiki/Roadmap) and [Issues Triaging](https://github.com/microsoft/vscode/wiki/Issues-Triaging) wiki pages, and [`.github/commands.json`](https://github.com/microsoft/vscode/blob/main/.github/commands.json).
- **robobun**: Bun's triage agent; for example its closing comment on [oven-sh/bun#44760](https://github.com/oven-sh/bun/issues/44760).
- **prisma/orm**: the record on branch [`docs/product-direction`](https://github.com/prisma/orm/tree/docs/product-direction), the first repository to use this skill.

## The parts of the record

| Project intent page                                                                                                             | Kody, `project-intent.md`                                                                                                                                                                                        |
| Its headings: what it is, who it is for, "Optimise for" and "does not need to optimise for", what not to assume, agent guidance | Kody, `project-intent.md`                                                                                                                                                                                        |
| "Read this file before making product-level decisions"; it wins when docs or code conflict                                      | Kody, `project-intent.md`                                                                                                                                                                                        |
| Vision with two parts, values and durable themes                                                                                | The Sweeper's vision has three layers, values, durable themes and current priorities, and names "guardrails" once without saying whether they are a fourth. We copy values and durable themes, the public layers |
| Values that do not change                                                                                                       | VS Code Roadmap: its five values have stayed nearly the same, and the team does not intend to change them                                                                                                        |
| Nothing about current work on the vision                                                                                        | The Sweeper's current-priorities layer is internal and paraphrase-only; none of 600 Sweeper records cites it. Kody's intent page holds only durable statements                                                   |
| Decision record sections Context, Decision, Consequences, and a Status                                                          | Nygard                                                                                                                                                                                                           |
| Statuses proposed, accepted, superseded                                                                                         | Nygard (who also has deprecated)                                                                                                                                                                                 |
| A Date line on each record                                                                                                      | Epic Stack; Kody, `0000-template.md`. Nygard's format has no Date field                                                                                                                                          |

| Write the context after the decision, not as a design brief                                                                     | Kody, `0000-template.md`                                                                                                                                                                                         |
| "No revisit-if condition is recorded"                                                                                           | prisma/orm, ADR 293, "Validations, soft delete and lifecycle hooks are not in the core"                                                                                                                          |

A repository's existing layout always wins                                                                                                    |

## The reading rules

| Element                                                                                                                                                | Source                                                                                                                                                                                                                                                                                                                             |
| ------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Verdicts `aligned`, `rejected`, `unclear`, `not_applicable`                                                                                            | The Sweeper, `visionFit`                                                                                                                                                                                                                                                                                                           |
| The fields `visionFit`, `visionFitReason`, `visionFitEvidence`, `bestSolution`; one sentence; the anchor cited                                         | The Sweeper                                                                                                                                                                                                                                                                                                                        |
| `rejected` when the request conflicts with a value or belongs elsewhere                                                                                | The Sweeper, `visionFit`, which is descriptive and never changes the triage action                                                                                                                                                                                                                                                 |
| Be conservative                                                                                                                                        | The Sweeper, `visionFit`: prefer `unclear` or `not_applicable` unless the vision speaks directly. What counts as speaking directly, and the record that only fixes a shape, have no direct source: they spell out that rule                                                                                                        |
| Name a missing part of the record                                                                                                                      | No direct source. Derived from the Sweeper's keep-open default ("when in doubt, keep it open")                                                                                                                                                                                                                                     |
| A decline needs an accepted record or a maintainer's earlier words; a value, a theme or the intent is never grounds, even where it quotes a maintainer | The Sweeper, `*extension-candidate`: an established maintainer position or clear precedent; "your own vision-fit read alone is evidence for `bestSolution`, not grounds to close". The "even where it quotes a maintainer" clause is this skill's, so that a quoted value is not read as the maintainer's own words on the request |
| A proposed decline states a confidence level; below high, no decline and `unclear`                                                                     | The Sweeper, `confidence`: a close proposal "should carry high confidence and at least one concrete `evidence` entry"; high (0.9 and above) needs direct proof, such as "an unambiguous policy match"; "when in doubt, keep it open". Giving `unclear` where the Sweeper keeps the item open is this skill's mapping               |
| A `rejected` verdict without grounds for a decline stays open, with where it belongs in `bestSolution`                                                 | The Sweeper, `visionFit`: "a poorly-aligned feature is not closed on vision grounds alone", and its third worked example, a `rejected` request kept open                                                                                                                                                                           |
| A Proposed record grounds nothing                                                                                                                      | Nygard: proposed means the stakeholders have not agreed yet                                                                                                                                                                                                                                                                        |
| "Already exists, use X", naming X; say what a partial match does and does not do                                                                       | The Sweeper, the existing-capability check and `*as-designed`: name the exact setting or command; a partial workaround is not coverage. `visionFit` is separate from the close reason, so it is judged as usual                                                                                                                    |
| "Already exists" is not a decline and needs no record                                                                                                  | No direct source. Derived: nothing was declined, and the shipped feature is the citation                                                                                                                                                                                                                                           |
| Earlier not-planned decisions are precedent only over the full scope                                                                                   | The Sweeper, precedent from a canonical issue closed as not planned                                                                                                                                                                                                                                                                |
| Never decline a change a maintainer in the thread proposed or accepted; name their direction                                                           | The Sweeper: where a maintainer in the thread has proposed or accepted a change, a decline close is off the table, and `bestSolution` names that direction                                                                                                                                                                         |
| A later maintainer comment declining it wins                                                                                                           | The Sweeper, the same paragraph: a later maintainer comment saying the request is out of scope overrides labels and milestones. This skill applies it to an acceptance too                                                                                                                                                         |
| An acceptance against an accepted record gives `unclear`, flagged                                                                                      | No direct source: the Sweeper's `visionFit` is separate from its close decision, so it has no rule here. Derived from its keep-open default                                                                                                                                                                                        |
| Contradicting maintainers give `unclear`, flagged                                                                                                      | No direct source. Derived from the Sweeper's keep-open default ("when in doubt, keep it open")                                                                                                                                                                                                                                     |
| No decline proposed for maintainer-filed, milestoned or security items                                                                                 | The Sweeper, hard keep-open rules: team-authored issues (author association `MEMBER`, `OWNER` or `COLLABORATOR`), issues with a release milestone, security issues                                                                                                                                                                 |
| When the thing to use instead does not exist, say so                                                                                                   | The Sweeper: only claim capabilities you can cite. Kody's template: name the existing primitive that covers the need                                                                                                                                                                                                               |
| A decline reply: verdict, evidence, workaround, what would be accepted, invitation to reopen                                                           | robobun, oven-sh/bun#44760 ("Where to start / what would be merged", a workaround, "Reopen with more context"); VS Code's `*out-of-scope` reply invites reconsideration                                                                                                                                                            |
| Propose; a maintainer acts                                                                                                                             | The Sweeper: read-only and proposal-only; every action is taken by a maintainer                                                                                                                                                                                                                                                    |
| Search earlier issues and maintainer comments when no record covers a request                                                                          | robobun, oven-sh/bun#44760, which cites a maintainer's earlier decision in oven-sh/bun#2632                                                                                                                                                                                                                                        |
| Decide direction before a detailed code review                                                                                                         | prisma/orm, `docs/oss/pr-triage.md`, step 5                                                                                                                                                                                                                                                                                        |
| Asked to build what an accepted record rules out: quote it and ask whether to supersede it                                                             | Kody and Nygard: a decision changes only by a new record that supersedes it                                                                                                                                                                                                                                                        |
| The rules live only in this skill; repositories link to them                                                                                           | No external source. One copy cannot drift from another                                                                                                                                                                                                                                                                             |

## Recording a new no

| Element                                                                          | Source                                                                                                                                                     |
| -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Drafted by an agent as proposed until a maintainer accepts it                    | Kody, record 0069, "proposed (needs Kent approval before treating as accepted)", set to accepted in [kody#3597](https://github.com/kody-hq/kody/pull/3597) |
| A maintainer's approval of the pull request accepts it                           | prisma/orm, `docs/oss/governance.md`: decisions are maintainer consensus on the thread, and an approval is that consensus                                  |
| The record goes in the same pull request as the change that carries the decision | Kody, for example [kody#3726](https://github.com/kody-hq/kody/pull/3726) and [kody#3806](https://github.com/kody-hq/kody/pull/3806)                        |
| Drafted from the maintainer's words, quoted with the date                        | Kody: Kent's decisions are quoted with a dated tag, such as "(Kent, 2026-10-16)"                                                                           |

## Corrections to earlier versions of this list

- Nygard's format has no Date field. The Date line comes from the Epic Stack and Kody.
- The Sweeper's vision has three named layers, values, durable themes and current priorities, plus "guardrails", named once without saying whether it is a layer. This skill copies values and durable themes.
- VS Code keeps feature area owners in `.github/classifier.json`, not on its Feature Areas wiki page.

## Left out

- **Current priorities and guardrails** from the Sweeper's vision: the first is internal to VS Code, and the policy does not say what the second is.
- **A roadmap**: VS Code's is 32 months past its yearly cycle, and the process runs without it.
- **Feature areas and owners**: routing to owners is process. VS Code keeps them in `.github/classifier.json`.
- **Labels, canned replies, bots and timers**: process, decided by each repository.
