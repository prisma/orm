# Decision records

Open the steering list below before you propose a new feature or surface, or judge a feature request or a pull request. This folder records product decisions already made, usually a no with what would reopen it. How to judge a request is in the [vision](../vision.md#how-to-use-this-page).

## When to add a record

Write one after a maintainer has decided not to build something the next agent would otherwise propose again. Copy the [template](./0000-template.md) to the next unused number with a short slug. Half a page is enough.

Do not write one for every pull request, or for a layout tweak or a library choice, unless that choice is a no that would otherwise be argued again.

Whoever declines a request for a reason no record covers drafts the record from the maintainer's words, with status `Proposed`. A maintainer's approval of that pull request accepts it: the drafter then sets the status to `Accepted` and adds the entry below.

To change a decision, write a new record and mark the old one `Superseded by NNNN`. Never edit or delete the old one. Move it to [Historical](#historical).

## Steering list

Each entry is an accepted no and what to use instead. Proposed records are not decisions, so they are not on this list.

- [NNNN: Short title that states the no](./NNNN-slug.md). Use instead: [the existing feature].
