# Developing @prisma/orm-better-auth

Notes for people who change this package. For how to use it, see the [README](README.md). For why it is built as it is, see [ADR 328](../../../../docs/architecture%20docs/adrs/ADR%20328%20-%20A%20library%20integration%20uses%20only%20published%20entrypoints%20and%20its%20models%20live%20in%20the%20application%20contract.md).

## Rules the package keeps

- `src/` imports only `@prisma/orm-framework`, `@prisma/orm-family-sql` and `@better-auth/core`, plus `@prisma/orm-toolchain/config-loader`, `node:fs/promises` and `node:path`, which only `src/generate/` imports, with a dynamic `import()`. It imports no private package of the Prisma repository and no database package. `pnpm lint:consumer-internal-imports` refuses `@internal/*` names and `test/repository-packages.test.ts` refuses `@repo/*` names. `test/source-imports.test.ts` refuses a `@prisma/` package that is not a peer dependency, which keeps out every database package.
- Errors the package raises are `BetterAuthError`s, because Better Auth and its command-line program recognise that class. Errors from the Prisma client pass through unchanged.
- No classes in `src/`, and nothing in `src/` imports a Node-only module or Prisma's tooling when the module loads. The package follows the rules Better Auth's `AGENTS.md` sets for code in Better Auth's own repository, which forbid classes and runtime-specific APIs. Loading Prisma's tooling only on demand also keeps an application that loads the adapter from loading it and the PSL parser. `createSchema`, which runs only under `auth generate`, loads `src/generate/` with a dynamic `import()`; only `src/generate/` imports the PSL parser, and it too loads the toolchain and Node modules with a dynamic `import()`. `test/source-imports.test.ts` checks these imports.

## What the adapter knows about each database

The adapter supports Postgres. It also ships a SQLite support, at the same proof-of-concept level as Prisma 8's SQLite package: its tests and Better Auth's suites run on it, and the README promises nothing beyond that.

Everything the adapter must know about one database is in that database's target support, in `src/targets/`: `postgres.ts` and `sqlite.ts`. The interface, `TargetSupport`, and the lookup are in `src/target-support.ts`; the interface is internal until the MySQL and MariaDB supports have shaped it. The adapter refuses a client that is not for a SQL database, then looks up the support whose `target` is the client's `contract.target`, and refuses the client when none is. A support states:

- `valueKind`: the kind of JavaScript value each codec reads and writes, which the contract check compares with what Better Auth needs. Nothing Prisma publishes gives that at run time. A codec the support does not know is accepted.
- `compareText`: the condition for every comparison of a text column Better Auth asks for (`eq`, `ne`, `in`, `not_in`, `contains`, `starts_with`, `ends_with`, each respecting or ignoring case). A field holds text when the ORM offers `like` on it, which it does only for a codec with the `textual` trait; a text filter on any other field is refused. The adapter answers an empty pattern (any value that is not null) and an empty list itself, so a support never sees them.
- `defaultNamespace`: the namespace a model declared outside any `namespace` block belongs to. The adapter needs it only for models the contract does not have yet: to print them in the contract check's message and in `auth generate`, and, in `auth generate`, to place the models the source file declares outside a `namespace` block. Models the contract has carry their own namespace. The target's descriptor records the default (`defaultNamespaceId`), and a test checks that each support agrees with it.
- `pslType`: the PSL type the contract check and `auth generate` print for a Better Auth field.

The supports contain codec ids, SQL text and functions only, and import no database package: `test/source-imports.test.ts` fails if any module in `src/` imports a `@prisma/` package that is not a peer dependency, type-only imports included. `test/source-literals.test.ts` fails if a literal or a name outside `src/targets/` and `src/exports/` contains a target name in any case (`pg/`, `PostgreSQL`, `isMysqlClient`) or is a codec id, and if a module outside those two folders imports any module of `src/targets/` other than `shipped.ts`. `src/exports/` is exempt because it will re-export the supports by name; the same test keeps it to re-exports only. `test/targets/shipped-supports.test.ts` reads every codec the published Postgres and SQLite target packages register and fails on one whose value kind the support does not state; when a target package adds a codec, add it to that support.

The types a support sees are the ORM's published ones: a text column is an `Expression` with the `ComparisonMethods` of a `textual` codec, and the functions are the `raw`, `eq` and `ne` of `OrmFunctionsOf`, both from `@prisma/orm-family-sql/orm-client`. The adapter reaches fields by run-time name, so it checks that a field is such a column with `isExpression` and the methods `like` needs, before it hands the field to a support.

Gaps in what Prisma publishes, which the supports work around:

- No published value says which kind of JavaScript value a codec reads, so each support keeps that table.
- Nothing the adapter can read at run time names the default namespace. The runtime client carries the contract but not the target's descriptor; the runtime part of the descriptor leaves out `defaultNamespaceId`; and the emitted contract lists the default namespace among its storage namespaces without marking it, so a contract with models in `public` and in `auth` does not say which is the default. `auth generate` could read the descriptor from `prisma.config.ts`, but it reads that file only when Better Auth passes no `--output`, and the contract check, which runs in the application, needs the same answer. So each support states it once, and both read it there.
- Postgres's `citext` extension codec is `textual`, so text filters accept it, but its `=` ignores case, so even a case-sensitive `eq` on a `citext` column matches another case.

Table and column names are compared exactly, letter case included. `auth generate` compares them to find a model or field your contract already stores in the table or column Better Auth needs, under another name. On Postgres an exact comparison is right. SQLite ignores the case of the letters A to Z in names, so a model whose table name differs only in case is not found there; SQLite then refuses to create the second table when the migration runs, which reports the clash; the same holds for two columns in one table. Matching SQLite's rule in the adapter would repeat what Prisma's SQLite package already knows for its migration planner, for a database Prisma 8 offers only as a proof of concept.

## How `auth generate` edits the contract

`createSchema` (`src/generate/`) reads the contract's PSL source files, from `--output` or from the contract inputs in `prisma.config.ts`, and parses them with the published syntax tree (`@prisma/orm-framework/psl-parser/syntax`). It inserts the lines `printPsl` prints at positions from that tree: fields after the line of the model's last field, new models at the end of the file. It never reformats or reprints the file. Before it returns the file, it parses the edited source files again and runs Prisma's published symbol table over them (`buildSymbolTable` from `@prisma/orm-framework/psl-parser`), and refuses if that reports a diagnostic the original files did not have. The binder and interpreter would check more, but they need the target's descriptors, which the adapter does not have. It returns the whole file, at its absolute path because Better Auth joins a relative path with its `--cwd`, with `overwrite: true`, and Better Auth asks and writes it; the adapter writes no file. Whenever the edit is anything but additions it can place in one file, it throws the contract message instead. When the contract has a problem that is not a missing model or field, the message is all it throws, because the message already lists the changes to make. In every other case it adds a line that says why nothing was written.

## Choices that look wrong but are deliberate

- **`src/generate/` is tooling code in a package registered as runtime plane.** It runs only under `auth generate`, never while an application serves requests, and it loads the PSL parser and Prisma's tooling. `architecture.config.json` still registers the whole package as one runtime-plane package. Splitting it would need the contract comparison (`src/contract/`, `src/models/`) in a shared plane and an exception for the adapter's dynamic import of `src/generate/`, and the plane rules allow no exception: `pnpm lint:deps` counts a dynamic import as a dependency. The property that matters is that nothing in `src/generate/` loads when an application serves requests, and `test/source-imports.test.ts` checks it.
- **The adapter id is `prisma-8`, not `prisma`.** Better Auth's command-line program treats the id `prisma` as its own Prisma 7 adapter.
- **Pattern filters (`contains`, `starts_with`, `ends_with`) do not use `LIKE`.** Prisma 8's `like` has no escape clause, so `%` and `_` in a value would act as wildcards, and SQLite's `LIKE` ignores ASCII case. The Postgres and SQLite supports compare raw string expressions instead, which is the same SQL on both databases (`src/targets/substring-text.ts`).
- **MySQL and MariaDB are refused.** No support ships for them yet. The Postgres and SQLite SQL would be wrong there: `length()` counts bytes, and the default collation ignores case. Their supports need their own text comparisons, and Better Auth's suites must run on those databases first.
- **`consumeOne` and `incrementOne` are not implemented.** Better Auth then uses its own fallback, a read followed by a guarded delete or update. The ORM's `delete()` can delete one row and return it in one statement where the contract reports the `returning` capability, so `consumeOne` can be built on it; that is planned. `incrementOne` needs an update by an expression such as `count = count + 1`, which the ORM does not have yet (prisma/orm#30808).
- **JSON and list fields are stored as text.** The adapter tells Better Auth it supports neither, so Better Auth serialises them.
- **Every read, update and delete applies a filter, even an empty one (`all()`).** The Prisma client's `update`, `updateAndCount` and `deleteAndCount` require an earlier `where(...)`. Its types enforce this, and the adapter's loose types would not show that it was missing.
- **The peer range for `@better-auth/core` stops below the next minor version.** The contract check is registered through `registerSchemaCheck` from `@better-auth/core/db/internal`, which Better Auth labels internal. The module is imported as a namespace and the function is used only when it exists, so a release that removes it leaves the adapter working without the check. Widen the range only after running the conformance suites against the new minor version. The range starts at 1.7.22: releases from 1.7.6 to 1.7.21 run the contract check when the auth instance is created, and log a contract that is missing something as a database connection problem.
- **Each target support keeps its own table of the kind of JavaScript value each codec reads.** Nothing Prisma publishes gives that at run time. It marks a gap to close in the published packages; remove the tables when one does.
- **The inside is loosely typed.** No published type says "a client whose contract contains these models". Correctness comes from the contract at run time, the contract check and the tests.

## Tests

- `test/conformance/` runs Better Auth's own adapter suites on Postgres and, as a proof of concept, SQLite. No test in them is disabled, and none may be.
- `test/targets/` checks the lookup and the shipped supports: each states a value kind for every codec its target package registers, and has its target descriptor's default namespace. These tests import the database packages; `src/` may not.
- `test/generate/` checks the edit: the whole edited text for each layout, that every edited contract emits and then has nothing missing, and each case where nothing is written.
- `test/integration/test/packaging/orm-better-auth-tarball.test.ts`, in the Prisma repository, installs the packed package with the lowest Better Auth release the peer range admits, outside the workspace. It checks that creating the auth instance logs nothing and that the first request fails with the message, and runs the real `auth generate` and `auth check`: one-file and two-file contracts, `--output` with and without `--cwd` and naming a directory, Better Auth's refusal to ask without a terminal, and the main cases where nothing is written. It compares everything the command prints on standard error. It runs in the merge queue, not on pull requests, so run that file locally when you change the contract check, `auth generate` or the manifest.
