# @internal/sql-contract-prisma7

Reads a Prisma 7 `schema.prisma` as a Prisma 8 contract source for the SQL family. During the side-by-side period Prisma 7 keeps owning the database and its migrations; this package lets `prisma contract emit` and `prisma db sign` read that schema directly, so no second schema file is needed until cutover.

## Responsibilities

- `prisma7Contract(path, options)` returns a `ContractConfig` (format `psl`, because a Prisma 7 schema is PSL text) whose `source.load` reads the input, parses every `.prisma` file with `@internal/psl-parser`, and runs the Prisma 7 interpreter. The source declares `parserOptions: { grammar: 'prisma-7' }`, so the parser reads a `view` body as model fields and the interpreter can refuse the view by name. A file input reads that file; a directory input reads every regular `.prisma` file under it, nested directories and symbolic links included, sorted by path, as Prisma 7 reads a schema directory. The default `output` is `contract.json` in the directory that holds the file or the directory, never inside the directory and never named after the file; `options.output` overrides it.
- The interpreter turns the Prisma 7 dialect into a validated SQL contract using the same lowering helpers as `@internal/sql-contract-psl`: models, columns, native types, namespaces (`@@schema`), and native enums. Every construct it does not support is a diagnostic with a span; nothing is changed silently.
- `Prisma7TargetBinding` (`src/target-binding.ts`) declares everything a target supplies to the interpreter: the target pack and namespace factory, the datasource providers it reads, the type map, the native enum names, how the datasource `extensions` list is read (the preview feature Prisma 7 requires, the extension entity kind, and each extension an extension pack declares, with the pack's id and published import), the index types, the identifier byte limit, the names the target derives for an unnamed primary key and foreign key (`defaultConstraintNames`), and how literal defaults are read for columns whose codec does not take the written value. The Postgres binding is `prisma7PostgresBinding` in `@internal/target-postgres/prisma7-binding`; its type map is derived from what `prisma@7.10.0` creates for the reference schema in `test/integration/test/fixtures/prisma7-source/reference/`.

## Usage

```ts
import { definePrismaConfig } from '@prisma/cli-engine';
import { defineConfig as ormConfig, prisma7Schema } from '@prisma/orm-postgres/config';

export default definePrismaConfig({
  orm: ormConfig({
    contract: prisma7Schema('prisma/schema.prisma'),
    db: { connection: process.env['DATABASE_URL']! },
  }),
});
```

The package itself is target-neutral: everything specific to a database comes from the target binding, which the Postgres facade passes in.

## Rule table, in short

| Prisma 7 | Contract |
|---|---|
| `model` | Model named verbatim; table is `@@map` or the name; column is `@map` or the field name. |
| `enum` | Native enum type named by `@@map` or the enum name, members in order, each member's value its `@map` or its name; placed in the enum's `@@schema`. |
| `@@schema("s")` | Namespace `s`; without it, the target's default namespace. |
| Datasource `extensions = [...]` | Read only with the `postgresqlExtensions` preview feature in a generator block, as Prisma 7 requires. An extension an extension pack declares (`vector` for pgvector, `postgis` for PostGIS, `pg_search` for ParadeDB) adds nothing to the contract when the config composes the pack, because the pack's own contract declares it, unless the entry puts it in another schema than the pack's contract does (its `schema:` argument, or the default namespace without one), which is an error; when it does not, an error naming the import and the `extensions` entry to add to `prisma.config.ts`. Every other extension is an `extension` entry in the namespace of its `schema:` argument, or the target's default namespace; the namespace is created even when no model uses it. Of two entries for one extension the first is kept. `version:` and `map:` are errors naming the edit. The contract records every composed pack under `extensions`, as the Prisma 8 schema reader does. |
| Scalars and `@db.*` | The target binding's type map (`typeMap`), for example `DateTime` to `timestamp(3)` and `Json` to `jsonb`; on Postgres a `DateTime` reads a JavaScript `Date`, as Prisma 7 read it, and `@db.Date` and `@db.Time` read strings. Lists are nullable array columns with no derived element check. |
| `@default(...)` | Column defaults through the target's default function registry, literals, list literals, enum members; `now()` is both the column default and the `now` generator on create, resolved for the column's codec, as Prisma 8 PSL resolves `@default(now()) @onCreate(now())`, because Prisma 7's client filled it too; `uuid`, `ulid`, `nanoid`, `cuid` are client generators on create, resolved for the column's codec through the stack's generator function registry, as Prisma 8 PSL resolves `@onCreate(fn())` (`cuid` maps to `cuid(2)`); `dbgenerated("<sql>")` is a raw SQL default and `dbgenerated()` means no column default. On a list field, any function other than `dbgenerated` is `PSL.PRISMA7_UNKNOWN_DEFAULT`; write a list literal instead. |
| `@updatedAt` | `now()` resolved for the column's codec through the stack's generator function registry, on create and on update, as Prisma 8 PSL resolves `@onCreate(now()) @onUpdate(now())`; Postgres binds it to every `DateTime` column type, and a timestamp, `@db.Time` or `@db.Timetz` generator receives the column's precision. Beside `@default(now())`, the column default is kept too. On a field that is not a `DateTime`, on a list, or with a native type that is not a date or time, an error. |
| `@id`, `@@id` | Primary key, named by `map` or `{table}_pkey` cut to 63 bytes as Prisma 7 cuts it; the name is stated only where it differs from the target's own (see [Constraint names](#constraint-names)). |
| `@unique`, `@@unique`, `@@index` | Indexes named `{table}_{columns}_key` and `{table}_{columns}_idx` cut to 63 bytes as Prisma 7 cuts them, `map` overriding, `type` mapped. |
| Explicit relations | Foreign keys with `onDelete` `restrict` (any foreign key field required) or `setNull` (every field optional) and `onUpdate` `cascade` unless given, named by `map` or `{table}_{columns}_fkey` cut as Prisma 7 cuts it; paired through `@internal/sql-contract-psl/resolution`. |
| Implicit many-to-many | Junction `_AToB` or `_Name`: columns `A` and `B`, primary key `(A, B)` named `_AToB_AB_pkey`, index `_AToB_B_index`, cascading foreign keys `_AToB_A_fkey` and `_AToB_B_fkey`. |
| `@ignore`, `@@ignore` | Kept in storage, left out of the models ([ADR 267](https://github.com/prisma/orm/pull/30641)). An `@ignore` field becomes a column of its model's table with its column default, its uniques, indexes and foreign keys; an `@@ignore` model becomes a table with no model, with its columns, keys, indexes and foreign keys; an implicit many-to-many junction with an ignored side becomes a table with no model. Relations over them stay out of the domain. An `@ignore` field in a primary key, or one a relation that is not `@ignore` joins on, is an error. Ignored objects meet every other rule of this table too (codecs, index arguments, referential actions, defaults). A required `@ignore` column with no database default warns `PN_COLUMN_REQUIRED_UNMAPPED`, because no ORM insert into its table can succeed; in Prisma 7 terms, remove `@ignore`, make the field optional, or give it a database default. `contract print` refuses a contract with ignored storage until Prisma 8 has syntax for storage with no model (TML-3469), so keep the Prisma 7 schema as the contract source until then. |
| `Unsupported("X")` | A raw column ([ADR 273](../../../../docs/architecture%20docs/adrs/ADR%20273%20-%20A%20column%20of%20a%20type%20no%20data%20type%20claims%20is%20a%20raw%20column.md)): data type `sql/raw` with `{ sql: "X" }`, codec `sql/raw@1`, the text as written. The model gets no field for it, as Prisma 7's client had none; the column is kept on the model's table like an `@ignore` field's, with its uniques, indexes and `@ignore` foreign keys. `@default(dbgenerated("..."))` is its default, and `@ignore` changes nothing. When the schema loads, the reader checks that the text is one type name, but it does not check the text against the database: `Unsupported("int4")` loads, and `db verify` then reports the column with the text the database prints (`integer`), which is the text to write in the Prisma 7 schema; Prisma 7 plans nothing for that edit. A required one with no default warns `PN_COLUMN_REQUIRED_UNMAPPED`; in Prisma 7 terms, make the field optional or give it `@default(dbgenerated("..."))`. `contract print` refuses it until TML-3469, so keep the Prisma 7 schema as the contract source until then. |
| `view`, a type constructor other than `Unsupported`, an `Unsupported` text that is not one type name, unmapped `@db.*`, `@db.*` or a default other than `dbgenerated(...)` on an `Unsupported` field, `relationMode = "prisma"`, a datasource `extensions` list without the `postgresqlExtensions` preview feature, an extension whose pack the config does not compose, `version:` or `map:` on an extension, `@updatedAt` on a field that is not a single `DateTime` of a date or time native type, index arguments, an `@ignore` or `Unsupported` field in a primary key or joined on by a relation that is not `@ignore`, `SetNull` or `SetDefault` over a required field that cannot take it, a JSON `null` default, a model named like an implicit junction or mapped to its table, one relation name on implicit many-to-many relations between different models in the same schema | Hard errors (table below). |

## Diagnostics

Codes are prefixed `PSL.PRISMA7_`:

| Code | Meaning |
|---|---|
| `PSL.PRISMA7_PROVIDER_MISMATCH` | No `datasource` block, or its `provider` is not `postgresql` / `postgres`. |
| `PSL.PRISMA7_RELATION_MODE_UNSUPPORTED` | `relationMode = "prisma"`, or the older `referentialIntegrity = "prisma"`. |
| `PSL.PRISMA7_VIEW_UNSUPPORTED` | A `view` block. |
| `PSL.PRISMA7_UNSUPPORTED_TYPE` | An unknown field type, or a type constructor other than `Unsupported(...)`. Or an `Unsupported(...)` that is not one double-quoted string (`Field "Post.search": Unsupported(...) takes one string, the column's type as the database prints it, such as Unsupported("tsvector").`), or whose text is not one type name (`Field "Post.search": Unsupported("tsvector; drop") is not one type name: <reason>`, where the reason is the `sql/raw` data type's). |
| `PSL.PRISMA7_NATIVE_TYPE_UNSUPPORTED` | A `@db.*` type with no Prisma 8 codec (`Citext`, or any unknown spelling), on an ignored field or model too. |
| `PSL.PRISMA7_EXTENSIONS_PREVIEW_FEATURE_MISSING` | The datasource lists `extensions` and no generator block lists the `postgresqlExtensions` preview feature; Prisma 7 refuses the schema too. Add the preview feature. |
| `PSL.PRISMA7_EXTENSION_PACK_MISSING` | A listed extension is declared by an extension pack the config does not compose (`Extension "vector" is declared by the "pgvector" extension pack, which is not available. Add the pack to extensions in prisma.config.ts: import pgvector from '@prisma/orm-extension-pgvector/control', then extensions: [pgvector].`). |
| `PSL.PRISMA7_EXTENSION_ARGUMENT_UNSUPPORTED` | An extension argument the contract cannot describe: `version:`, because the contract does not record an extension's version (remove it; Prisma 7's next migration is then empty), or `map:` (write the extension by its database name instead; when that name is not one Prisma 7 can write without `map`, the schema cannot be read yet). Also an argument Prisma 7 refuses too: one without a name, an unknown one, or a `schema:` that is not a string. |
| `PSL.PRISMA7_EXTENSION_SCHEMA_MISMATCH` | A listed extension a composed pack declares is put in another schema than the one the pack's contract declares it in. Prisma 8 expects it in the pack's schema, and moving it is a database change the pack does not make; the message names the `ALTER EXTENSION ... SET SCHEMA` and the edit to the entry. |
| `PSL.PRISMA7_ENUM_NAMESPACE_MISMATCH` | A field uses an enum declared in a different `@@schema`; a Postgres enum type lives in one schema and Prisma 8 columns reference the enum of their own namespace. |
| `PSL.PRISMA7_RELATION_UNRESOLVED` | A relation field that cannot be paired: no matching side, an ambiguous unnamed pair, a singular back-relation over a non-unique foreign key, a `fields`/`references` mismatch, or a required relation field over an optional foreign key field. |
| `PSL.PRISMA7_REFERENTIAL_ACTION_UNSUPPORTED` | `SetNull` on a relation over a required field, or `SetDefault` over a required field with no column default. |
| `PSL.PRISMA7_JUNCTION_ID_UNSUPPORTED` | An implicit many-to-many relation on a model without a single-field `@id` (a composite id, for example). Prisma 7 forbids it too. |
| `PSL.PRISMA7_JUNCTION_NAME_COLLISION` | A model in the same schema as an implicit many-to-many junction has the junction model's name (`PostToTag`, or the relation name). |
| `PSL.PRISMA7_RELATION_NAME_SHARED` | Two or more implicit many-to-many relations in the same schema use the same relation name; Prisma 7 creates one table for all of them, wired to only one. The same name in two schemas is fine: Prisma 7 creates a table in each. |
| `PSL.PRISMA7_UNKNOWN_ATTRIBUTE` | An attribute Prisma 7 for Postgres does not have, or one this source does not read (`@@fulltext`, `@shardKey`, ...), or `@db.*` on an `Unsupported` field, which Prisma 7 refuses too. |
| `PSL.PRISMA7_UPDATED_AT_FIELD_INVALID` | `@updatedAt` on a field whose type is not `DateTime`, on a list field, or on a `DateTime` field whose native type is not a date or time, such as `@db.Text`. Prisma 7 refuses all three too. |
| `PSL.PRISMA7_TABLE_COLLISION` | Two models map to the same table in the same schema, reported on every model in the group; or a model maps to the table of an implicit many-to-many relation, reported on the model's `@@map` and on the relation field. |
| `PSL.PRISMA7_GENERATOR_REFUSED` | A client function in `@default` the column refuses, such as a Nano ID that does not fit its column. `@db.Char(10) @default(nanoid())` is the one shape `main` read that the source now refuses; Postgres refuses the insert, so no Prisma 7 application could store such a row. `@db.VarChar(10) @default(nanoid(16))` was refused on `main` too, as `PSL.PRISMA7_UNKNOWN_DEFAULT`, because `main` bound `nanoid` to no `VarChar` column; it is now refused with this code. |
| `PSL.PRISMA7_UNKNOWN_DEFAULT` | A `@default` value this source cannot read: an unknown function, an enum member on a non-enum field, a non-member, a non-integer `BigInt` literal, a malformed JSON or base64 literal, a `dbgenerated(...)` argument list that is not a single positional string with text in it, or any default other than `dbgenerated(...)` on an `Unsupported` field, which Prisma 7 refuses too. |
| `PSL.PRISMA7_JSON_NULL_DEFAULT_UNSUPPORTED` | A `Json` default of `"null"`, or a `Json[]` default holding it: the JSON value null cannot be told apart from SQL `NULL` in the contract. |
| `PSL.PRISMA7_IGNORED_FIELD_REFERENCED` | An `@ignore` field, or an `Unsupported` field of a model that is not `@@ignore`, in `@id` or `@@id`: without it the model has no field that identifies a row. For `Unsupported`, add `@@ignore` to the model, which keeps its table and primary key. Or such a field that a relation which is not `@ignore` joins on through `fields:` or `references:`: Prisma 8 relations join on fields. For `Unsupported`, mark the relation field `@ignore`, which keeps its foreign key. |
| `PSL.PRISMA7_CONSTRAINT_NAME_TOO_LONG` | A `map` on `@id`, `@@id`, `@unique`, `@@unique`, `@@index` or `@relation` longer than the binding's `identifierMaxBytes` (63 bytes on Postgres). The database would keep the name cut short, so the source refuses it rather than change it; Prisma 7 refuses it too. |
| `PSL.PRISMA7_INDEX_ARGUMENT_UNSUPPORTED` | An index argument Prisma 8 cannot carry (`sort`, `length`, `ops`, an unknown type), a dotted path such as `title.length`, which Prisma 7 refuses as an unknown field, or a field that is not a column. |
| `PSL.PRISMA7_CONTRACT_INVALID` | A structured error (one with a dotted code, such as the contract builder's `CONTRACT.*` or a codec's `RUNTIME.*`) was thrown while `load` built the contract, or the contract failed the domain, storage consistency, or model storage reference check `load` runs afterwards. It is reported at the input path and asks the user to report the schema as a Prisma bug. Any other error thrown inside `load`, such as an `InternalError` or a `TypeError`, still throws: it is a bug in Prisma ORM, not a problem in the schema (ADR 245). |
| `PSL.PRISMA7_SCHEMA_READ_FAILED` | The input path could not be read, or a schema directory holds no `.prisma` file. |

Unknown top-level blocks keep the parser's `PSL_UNSUPPORTED_TOP_LEVEL_BLOCK` code.

## Relations

Explicit relations keep their fields, references, and actions; an omitted `onDelete` becomes `Restrict` when any foreign key field is required and `SetNull` only when every one is optional, as Prisma 7 writes them; a relation field may be optional over required fields, and its foreign key and relation are then those of a required relation; an omitted `onUpdate` becomes `Cascade`, and both are always written. `map` names the foreign key (see [Constraint names](#constraint-names)). One-to-one is recognised by `@unique` on the foreign key fields. An implicit many-to-many relation (a list field on both sides) becomes the junction Prisma 7 creates: model `AToB` (models in alphabetical order, or the relation name), table `_AToB`, columns `A` and `B` typed like the two ids, primary key `(A, B)`, index `_AToB_B_index`, two cascading foreign keys, and two relation fields named as `contract infer` names the same table's foreign keys. The target binding supplies the names (`junctionRelationFieldNames`); the Postgres binding gets them by running infer's PSL construction on the junction table. Infer names `A` and then `B` twice: first after the referenced table in camelCase, against the column names, appending the referenced model name and then a number when the name is taken; then against the fields `a` and `b` the columns print as, appending the first free number from 2. So `_PostToTag` gets `post` and `tag`, a self relation over `User` gets `user` and `userUser`, and `_AToB` over models `A` and `B` gets `a2` and `b2`. `A` is the model with the smaller name in plain string order; for a self-relation, the field with the smaller name, which is prisma-engines' own rule (`psl/parser-database/src/relations.rs`, `ingest_relation`). A relation field marked `@ignore`, or one to an `@@ignore` model, stays out of the domain on both sides and keeps its foreign key; an implicit many-to-many relation with an ignored side keeps its junction table as storage with no model. A relation field that is not ignored but joins on an `@ignore` or `Unsupported` field through `fields:` or `references:` is `PSL.PRISMA7_IGNORED_FIELD_REFERENCED`, because Prisma 8 relations join on fields. Pairing reuses `@internal/sql-contract-psl/resolution`.

`@id`, `@@id`, `@unique`, and `@@unique` are read because relations depend on them (one-to-one detection, junction column types). `@id` and `@@id` become the primary key. `@unique` and `@@unique` become unique indexes, not unique constraints, because that is what Prisma 7 creates, and `db verify` compares indexes by name.

## Defaults, generators, `@updatedAt`, and indexes

`@default(autoincrement())` and `@default(now())` become column defaults through the target's default function registry (`context.controlMutationDefaults`). `@default(now())` also becomes the `now` generator on create, resolved for the column's codec through the generator function registry, as Prisma 8 PSL resolves `@default(now()) @onCreate(now())`: Prisma 7's client filled the value itself and wrote the column default for other writers, so a create through Prisma 8 writes UTC whatever the session time zone, and an `INSERT` from outside Prisma still gets the column default. On a field that is not a `DateTime`, or on a `DateTime` field whose native type is not a date or time (`@db.Text`), it is `PSL.PRISMA7_UNKNOWN_DEFAULT`, as Prisma 7 refuses both. The ORM-side generators `uuid()`, `uuid(4)`, `uuid(7)`, `ulid()`, `nanoid()`, `nanoid(n)`, `cuid()`, and `cuid(2)` become execution generators on create with no column default. `cuid()` maps to `cuid2` because Prisma 7's `cuid()` is cuid v1, which Prisma 8 does not ship; the column type is the same and the ids are opaque, so existing rows keep working beside new ones. Every other call's arguments are bound through the target's signatures, as Prisma 8 PSL binds them: an argument the function does not take (`uuid(5)`, `cuid(1)`, `nanoid(1)`, `nanoid(1000)`, `nanoid(8.5)`) or a named argument (`nanoid(size: 8)`) is `PSL.PRISMA7_UNKNOWN_DEFAULT` at the argument, with the function's message, such as `Field "User.id": uuid: version must be 4 or 7, got 5`. `@default(dbgenerated("<sql>"))` becomes a raw SQL default carrying the string as written, without going through the registry; `@default(dbgenerated())` with no argument means the column has no default, on required, optional, and list fields alike. Literals of every scalar, list literals, and enum members (the member's mapped storage value) become literal defaults; a number literal is carried as the value the column codec reads: the number itself when the codec reads a JSON number, otherwise what the codec decodes from the literal exactly as written, so `Decimal` and `BigInt` defaults keep every digit and trailing zero (`"1.50"`, `"9007199254740993"`); a number with a fraction on an `Int` or `BigInt` field, or one the codec reads neither way, is `PSL.PRISMA7_UNKNOWN_DEFAULT`, as Prisma 7 rejects it, and the message says an `Int` or `BigInt` default must be a whole number; `Json` literals are parsed, and `Bytes` and `DateTime` literals are read through the column type's tag, as the current schema language reads them, and stored as values: a `Bytes` default's base64 as the hex body of `bytea`, stored as base64, and a `DateTime` default as the body that keeps what it means on the column: the written date on `date`, the written wall-clock time without its offset on `timestamp` and `time`, the time with its offset on `timetz`, and the written instant on `timestamptz`, stored in UTC (`2024-01-02T01:04:05Z`). A value with more fraction digits than its column holds (three on a plain `DateTime`, which is `timestamp(3)`) is `PSL.PRISMA7_UNKNOWN_DEFAULT`, and the message names the value PostgreSQL stores instead, rounded as PostgreSQL rounds it, to write in its place. Second 60, which PostgreSQL carries into the next minute, is refused with the tag's reason. A `Bytes[]` or `DateTime[]` list default stores each element the same way. A value the column's type holds but its codec cannot hold exactly, such as a `DateTime` default with digits below a millisecond on a column read as a JavaScript `Date`, is kept as the SQL expression the target binding writes for it (`literalDefaultExpression`), for the whole default, list or not. `@updatedAt` becomes an ORM-side "now" generator on create and update; the generator function registry picks the generator from the column's codec and type parameters, and on Postgres every date and time column type has one, each writing the current UTC time as the column's codec reads it (`timestampNow`, a `Date`, for a plain `DateTime` and a `@db.Timestamptz`, `dateStringNow` for `@db.Date`, and so on); the timestamp and `@db.Time(p)` and `@db.Timetz(p)` generators get the column's precision as their `precision` param and round down to it, so the client holds the value Postgres stores, which never rounds a `@db.Timestamp(0)` value up to the next second or a time up to `24:00:00`. `@updatedAt` on a field that is not a `DateTime`, on a list field, or on a `DateTime` field whose native type is not a date or time (`@db.Text`), is `PSL.PRISMA7_UPDATED_AT_FIELD_INVALID`, as Prisma 7 refuses all three. `@updatedAt` beside `@default(now())` keeps the column default as well, so writes outside the ORM still get a value. A generator or `@updatedAt` on an optional field gives a nullable column: a value the client leaves out is generated, and an explicit `null` is stored as `null`, as in Prisma 7. List columns decline the element-not-null check Prisma 8 would otherwise derive, because Prisma 7 creates none.

`@unique` and `@@unique` become unique indexes named `{table}_{columns}_key` and `@@index` becomes an index named `{table}_{columns}_idx`, `map` overriding either (`name` on `@@unique` is the client-side name and is ignored). A generated name is cut the way Prisma 7 cuts it to fit PostgreSQL's 63-byte identifier limit: the `{table}_{columns}` part is shortened to 63 bytes minus the suffix, on a character boundary, and the suffix stays whole (`AVeryLongModelNameThatKeepsGoingAndGoingForever_aVeryLongCo_idx`). The same rule cuts an implicit junction's table name (no suffix) and its `_B_index`. `db verify` compares indexes by name, so the contract must carry the name Prisma 7 created. `type: Hash` and the other Prisma 8 index types map through; field arguments such as `sort` and `length`, and `ops`, are `PSL.PRISMA7_INDEX_ARGUMENT_UNSUPPORTED` because Prisma 8 indexes carry none.

## Constraint names

`db verify` does not compare primary key or foreign key names, but the migration planner drops and renames constraints by name, so the contract must know the names Prisma 7 created wherever the planner would derive different ones. Prisma 7 names a primary key `map`, or `{table}_pkey`; a foreign key `map`, or `{table}_{columns}_fkey`; an implicit junction's primary key `_{name}_AB_pkey` and its foreign keys `_{name}_A_fkey` and `_{name}_B_fkey`. Each generated name is cut to 63 bytes as Prisma 7 cuts index names, keeping the suffix whole. A `map` is never cut: one longer than 63 bytes is `PSL.PRISMA7_CONSTRAINT_NAME_TOO_LONG`, as Prisma 7 refuses it. The source compares each name with the one the target derives for an unnamed constraint (`defaultConstraintNames`) and states it only where the two differ: every `map` that is not the derived name, every junction primary key, and every foreign key name Prisma 7 cut. Matching names stay unnamed, so `contract print` writes no `map` for them and a table rename keeps deriving them. The Postgres binding derives each name as Postgres stores it: a primary key name as Postgres names one itself, cutting the table name to keep `_pkey`, so a long table's primary key matches Prisma 7's and stays unnamed; a foreign key name cut at 63 bytes without keeping `_fkey`, so a foreign key name Prisma 7 cut is stated. Because whether a name is stated depends on the derived names, changing how the target derives them changes the storage hash of affected contracts and needs an upgrade instruction.

## Multi-file input

A directory input is read file by file in sorted path order, nested directories included, and a diagnostic names a nested file by its path under the directory (`prisma/schema/models/user.prisma`); the datasource check runs once over all of them. A dotted path in a `datasource` or `generator` value (`provider = prisma.client.js`) is `PSL_INVALID_EXTENSION_BLOCK_MEMBER`, because Prisma 7 accepts none there; so is an `extensions` value that is not a list, or an entry that is not an extension name, such as `"pg_trgm"`. A model or enum declared in more than one file is `PSL_DUPLICATE_DECLARATION` on the later file, the same code the parser's symbol table uses for a duplicate within one file.

## Tests

`test/fixtures/<case>/schema.prisma` with either `expected-contract.json` or `expected-diagnostics.json`; `test/fixtures.test.ts` runs every case through the real Postgres pack. Set `UPDATE_PRISMA7_FIXTURES=1` to rewrite the expected files after an intentional change. A case with a `composed-extensions.json` (a list of extension pack ids) is read with those packs composed.
