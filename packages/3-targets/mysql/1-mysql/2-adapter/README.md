# @internal/adapter-mysql

MySQL adapter for Prisma 8: query lowering for the runtime, and the control adapter.

## Package Classification

- **Domain**: targets
- **Layer**: adapters
- **Plane**: multi-plane (shared, migration, runtime)

## Purpose

Lowers the queries the ORM and the SQL builder build into MySQL SQL, and reads and writes a MySQL database for the control plane: introspection into the SQL family's schema IR, the marker and ledger, the marker lock, the control tables' DDL and transactions.

## Responsibilities

- **Capabilities**: `foreignKeys`, `orderBy`, `limit`, `enums` and `defaultInInsert`. Not `returning`, `lateral`, `insertOnConflictTarget` or `insertOnConflictSkip`: `ON DUPLICATE KEY UPDATE` fires on any unique key, and `INSERT IGNORE` would also hide foreign-key and `NOT NULL` errors. Without `returning` the ORM reads written rows back with a `SELECT` (see the [ORM client README](../../../../3-extensions/sql-orm-client/README.md#writes-without-returning)).
- **Introspection** (`src/core/migrations/introspection.ts`): reads `information_schema` for `TABLE_SCHEMA = DATABASE()`. A column's type is `COLUMN_TYPE` as reported; `EXTRA` marks `auto_increment` and expression defaults (`DEFAULT_GENERATED`), and an unquoted `COLUMN_DEFAULT` is a literal the column's codec reads. Unique constraints are split from plain indexes by `TABLE_CONSTRAINTS`, and the index InnoDB creates for a foreign key, which carries the key's name and columns, is left out. The mapping takes catalog rows, so it is tested without a server.
- **Column defaults in DDL** (`src/core/migrations/ddl-renderer.ts`): a literal default is encoded by the column's codec and written as a MySQL literal, in parentheses on a text, blob or JSON column. A `now()` default writes the current value the column's data type holds, with its fraction digits: `CURRENT_TIMESTAMP(p)` on a datetime, timestamp, text or raw column, `CURRENT_DATE` on a date and `CURRENT_TIME(p)` on a time. A `now()` default on a column whose data type holds no date or time, such as an int or a duration, is refused with `CONTRACT.DEFAULT_INVALID`.
- **Marker and ledger reads and writes**, **`withTransaction`** (`START TRANSACTION`), and the `CREATE TABLE IF NOT EXISTS` statements for the control tables. `initMarker` writes with `INSERT … ON DUPLICATE KEY UPDATE`, binding the values a second time for the update instead of naming a row alias, which MariaDB does not accept. MySQL has no `RETURNING`, so `updateMarker` reads and locks the row with `FOR UPDATE` inside the caller's transaction and writes it only when it still holds the expected hash.
- **`holdMarkerLock`** takes the marker lock, a `GET_LOCK` MySQL holds for the session, around the work it guards and releases it with `RELEASE_LOCK` when that work ends; `db sign` creates the marker table and writes the markers inside it. `lockMarker` takes no lock, because the lock is already held around the transaction. The migration runner takes the same lock through the same helper.
- **Query lowering** (`src/core/sql-renderer.ts`), the class `MysqlSqlRenderer`, used by the runtime adapter. It is built with the codecs and the target's runtime metadata, whose id and display name its errors carry. A database that extends MySQL subclasses it and overrides three protected methods; every other method is private. `proposedRow()` says how the upsert's `ON DUPLICATE KEY UPDATE` clause reads the proposed row (MySQL's row alias `new`). `returningRefusal(statement)` gives the message a refused `RETURNING` carries, so a database that has some `RETURNING` can say why it is not used. `orderedJsonArrayRefusal()` returns a message when the database cannot build an ordered JSON array, and the renderer then refuses an ordered to-many include with it; MySQL returns none:
  - Backtick quoting. Each parameter is written as `?N`, N being its position in `collectOrderedParamRefs`, the order the runtime encodes parameters in; a parameter written twice is bound once. `src/core/placeholders.ts` then checks that every placeholder names a parameter and every parameter has one, and raises `RUNTIME.PARAM_PLACEHOLDER_MISMATCH` otherwise, as for a `?` written into raw SQL text. The driver hands the values to the `mariadb` package, which writes them into the statement. Every parameter, an integer one included, is a bare `?N`, as the Postgres adapter writes `$N`. MySQL infers no type for a parameter: the package writes each value as a literal, and MySQL reads it as it reads any literal. The `bigint` codec returns a JavaScript `bigint`, which the package writes as bare digits, so MySQL reads it as an exact integer beside a column or an expression. Where nothing gives a parameter a type, as in `?1 + ?2` in raw SQL, the author writes the cast, as on Postgres. `LIMIT ?1` takes only a bare placeholder, so the adapter could not cast there in any case. A literal the AST carries is written inline only when it is a number, a bigint, a boolean or NULL, which only code writes, such as the ORM's `1`; a text, date or JSON literal is refused with `RUNTIME.AST_UNSUPPORTED`, because only a caller could supply it and a caller's value belongs in a param. `JSON_OBJECT` keys, which are contract field and relation names, are written through the target's `escapeLiteral`, which doubles quotes and backslashes.
  - `<=>` for IS NOT DISTINCT FROM, a leading `x IS NULL` sort key for NULLS FIRST and NULLS LAST, the largest row count MySQL takes for an `OFFSET` with no `LIMIT`.
  - A to-one include and an unordered array use `JSON_ARRAYAGG`. A to-many include with an order uses `GROUP_CONCAT(… ORDER BY …)` cast to JSON, because `JSON_ARRAYAGG` takes no `ORDER BY`; the statement raises `group_concat_max_len` itself with a `SET_VAR` hint, so it does not depend on the driver's session. An include with no rows is `JSON_ARRAY()`. Text longer than `max_allowed_packet` makes MySQL's `CONCAT` return NULL with only a warning, so a NULL array with rows fails the statement instead of reading as empty. MySQL reports that failure as `Invalid JSON text in argument 1 to function cast_as_json`, which names neither the include nor `max_allowed_packet`: the driver cannot tell it from any other invalid JSON cast, so it passes the error on unchanged. This size limit applies only once an include has an order.
  - Writes: `INSERT` with the bare table name, since MySQL's `INSERT` takes no alias, so a column of the table is qualified by the table's name, and `DEFAULT` where a row of a multi-row insert has no value; `UPDATE` and `DELETE` with the table alias. An upsert is `INSERT … AS new ON DUPLICATE KEY UPDATE`, with the proposed row, which the AST names `excluded` as Postgres does, written `new`.
  - Refused with `RUNTIME.AST_UNSUPPORTED`: FULL and LATERAL joins, function sources, row locks, DISTINCT ON, non-finite numbers, `RETURNING`, an insert that skips conflicting rows, and an upsert that names its conflict columns, since `ON DUPLICATE KEY UPDATE` cannot be limited to them.
  - Also refused with `RUNTIME.AST_UNSUPPORTED`: an `UPDATE` or `DELETE` whose filter or values read the table it writes, which MySQL refuses with error 1093. The ORM sends one from `updateAll`, `deleteAll`, `updateAndCount` and `deleteAndCount` whose filter goes through a relation from a model to itself or that run on a variant stored in its own table, and from `update` and `delete` whose filter goes through such a relation and names a unique key (without one, they read the row first and write it by key). The error's `fix` tells the user to read the keys of the rows, and any values the write takes from the table, with a query first, then update or delete those rows by key with those values (for a variant, one row at a time with `update` or `delete`). The filter is checked only when that query runs, so a row another transaction changes in between is still written. MariaDB runs these statements, so its renderer writes them. The renderer does not rewrite them, because the only form MySQL accepts reads the table through a derived table, which copies the table and locks every row it copies, so concurrent writes can deadlock: 16 concurrent single-row writes through the ORM on a 10,000-row table deadlocked (error 1213) in every run we measured.
- **Runtime adapter** (`./runtime`): `createMysqlRuntimeAdapterDescriptor({ descriptorMeta, target, renderer })` builds it from the adapter metadata, the target's runtime metadata and a function that builds the renderer; MySQL's descriptor is that applied to MySQL's values. The profile id is derived from the target id (`<targetId>/default@1`), and the profile's `target` is the target id. It lowers with the renderer, infers a codec for bare values in raw SQL, registers the `now()` generators of the date and time types, and reads the marker from the control tables through `src/core/marker-read.ts`, which the control adapter shares.
- **Not yet built**: the control adapter's own query lowering, which still refuses with `RUNTIME.AST_UNSUPPORTED`; the control plane runs SQL text.

## Driver contract

The SQL this adapter lowers is not runnable as written: each parameter is a numbered `?N`, which MySQL does not read. A driver used with this adapter must rewrite each `?N` to MySQL's positional `?`, order the values to match, and have its client library write them into the statement, never writing a value into SQL itself. `@internal/driver-mysql` does this, and the `mariadb` package writes each value. The adapter writes no casts on parameters. The package writes a number as its digits, so `LIMIT ?1` takes an integer of any size. The driver's rules for the values it refuses are in [`parameter-values.ts`](../3-driver/src/core/parameter-values.ts).

## Exports

- `./runtime`: the runtime adapter descriptor and `createMysqlRuntimeAdapterDescriptor`
- `./control`: the control adapter descriptor, `buildMysqlSchemaIR`, and for a target that extends MySQL `createMysqlControlAdapter`, which takes the target id from the control stack and a catalog reader from its options, and `readMysqlCatalog` with its queries `MYSQL_CATALOG_QUERIES` and the row types `MysqlCatalogRows` and `MysqlColumnRow`
- `./sql-renderer`: `MysqlSqlRenderer` and the types its protected methods take and return (`ProposedRow`, `ReturningStatement`). It exists only so a target that extends MySQL can subclass the renderer, and exports nothing else
- `./adapter`: capabilities, contract contributions (the capabilities and the target's aggregate descriptors) and the adapter descriptor metadata
- `./codec-types`: the `CodecTypes` an emitted `contract.d.ts` imports
