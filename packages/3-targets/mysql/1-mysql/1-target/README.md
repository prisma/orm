# @internal/target-mysql

MySQL target pack for Prisma 8.

## Package Classification

- **Domain**: targets
- **Layer**: targets
- **Plane**: multi-plane (shared, migration, runtime)

## Purpose

Declares what MySQL is to the SQL family: its data types, codecs and PSL scalars, its single namespace, the control tables, and the control target descriptor that projects a contract onto the schema IR introspection compares it with.

## Responsibilities

- **Descriptor metadata**: `targetId: 'mysql'`, `supportsNamespaces: false` and the unbound default namespace ([ADR 223](../../../../../docs/architecture%20docs/adrs/ADR%20223%20-%20Target-owned%20default%20namespace.md)). Namespace blocks are refused through that flag, with the display name and reason the descriptor supplies.
- **Data types** (`src/core/data-types.ts`, [ADR 254](../../../../../docs/architecture%20docs/adrs/ADR%20254%20-%20Data%20types%20and%20casts.md)): `mysql/int`, `mysql/bigint`, `mysql/decimal`, `mysql/double`, `mysql/boolean` (`tinyint(1)` only), `mysql/longblob`, `mysql/json`, `mysql/varchar`, `mysql/char`, `mysql/text`, `mysql/datetime`, `mysql/timestamp`, `mysql/date`, `mysql/time`, `mysql/duration` and `mysql/enum`. PSL `String` is `varchar(191)`, so a `@unique` column can be indexed. A PSL number with a fraction, or a whole number past 64 bits, is a `mysql/decimal`; `true` and `false` are `mysql/boolean`; the `longblob` tag writes bytes as hex text and the `json` tag a JSON document. `mysql/enum` is a native `enum('A','B')` column type whose name is the text MySQL's catalog prints, so `db verify` compares the members and their order.
- **Scalar types** (`src/core/type-constructors.ts`, [ADR 322](../../../../../docs/architecture%20docs/adrs/ADR%20322%20-%20Each%20target%20declares%20the%20scalar%20convenience%20types%20over%20its%20own%20explicit%20types.md)): the explicit types `Int4`, `Int8BigInt`, `Int8Number`, `Float8`, `NumericString`, `Varchar`, `Text`, `Bool`, `Longblob` and `PlainJson` name one codec each. The convenience types `Int`, `BigInt`, `Float`, `Decimal`, `String`, `Boolean`, `Bytes` and `Json` choose one with `storage:` and, for `BigInt`, `as:`; a bare `Decimal` is `NumericString(65, 30)` and a bare `String` `Varchar(191)`. `Float` takes `storage: double` only, because a `float` column reads back from a row rounded to six significant digits.
- **Date and time types** ([ADR 315](../../../../../docs/architecture%20docs/adrs/ADR%20315%20-%20Each%20target%20declares%20the%20convenience%20date%20and%20time%20types%20over%20its%20own%20explicit%20types.md)): the explicit types `DatetimeJsDate` (`mysql/datetime@1`), `DatetimeTemporal`, `DatetimeString`, `TimestampJsDate`, `TimestampTemporal`, `TimestampString`, `DateString`, `DateTemporal`, `TimeString`, `TimeTemporal` and `DurationString` name one codec each (`src/core/date-time-codecs.ts`); each but the date and duration types takes a `precision`, 0 to 6, and a bare MySQL type holds no fraction of a second. The convenience types `DateTime`, `Date`, `Time` and `Duration` choose one with `as:` and `storage:` (`src/core/type-constructors.ts`, ADR 279); a bare `DateTime` is `DatetimeJsDate(3)`, the type `DateTime` named before. A row that reads a `Date` defaults to precision 3 and every other row to 6. Every instant is read and written in UTC, which every session runs in. A write refuses a value its column does not hold: a `datetime` or `date` before the year 1000, a `timestamp` outside 1970-01-01T00:00:01 to 2038-01-19T03:14:07.999999, a `time` that is no time of day, or digits below a microsecond; A write rounds a `datetime`, `timestamp` or `time` value down to the precision its codec reference names, since MySQL would round it to the nearest digit, which can carry `23:59:59.6` to `24:00:00`. A `datetime`, `timestamp` or `time` column written without a precision records precision 0 in the contract's storage (`src/core/mysql-database.ts`), so only a raw parameter that names no precision is written whole. A read takes what MySQL returns in any year; only `TimeString` and `TimeTemporal` refuse to read a row, a `time` such as `-01:00:00` or `838:59:59`. `mysql/duration` is stored in a `varchar(191)` column (`storedAs: mysql/varchar`), as an ISO 8601 duration as written, so that a `Duration` field can be indexed. PSL writes defaults with the `datetime`, `timestamp`, `date`, `time` and `duration` tags. A literal default with more fraction digits than its column's precision, 0 when none is written, is refused, since MySQL would round it. `@default(now())` renders `CURRENT_TIMESTAMP(p)` on a datetime, timestamp, text or raw column, `CURRENT_DATE` on a date and `CURRENT_TIME(p)` on a time; the default normalizer names the instant `now()`, and MySQL's `curdate()` and `curtime(p)` `CURRENT_DATE` and `CURRENT_TIME`, so changing a field between `DateTime`, `Date` and `Time` is a change the planner and `db verify` see. The `now()` generators (`src/core/date-time-now-generators.ts`) round down to the column's precision, since MySQL rounds a value to it. The database-agnostic logic comes from `@internal/type-implementations`. Only the control entry sets the `Temporal` fallback; without a global `Temporal` and with no control entry loaded, the Temporal codecs, when they decode, and the `instantNow`, `plainDateNow` and `plainTimeNow` generators raise `RUNTIME.TEMPORAL_UNAVAILABLE`.
- **Enum columns** (`src/core/mysql-database.ts`): the namespace factory writes each enum column's members, from the value set the column names, into its type parameters in declared order. No CHECK constraint is derived.
- **Codecs**: at least one per data type, plus MySQL adaptations of the family's `sql/char@1`, `sql/varchar@1` and `sql/raw@1`. Each `fromWire` reads what the driver hands over: the text MySQL sends, for every column; an include's JSON carries an `int` as a number. `projectJson` writes a column into the JSON an include reads, in the form its `fromWire` reads from a row: `int`, the text types, `enum` and the date and time types pass through; `bigint` renders as `CAST(x AS CHAR)`, because JavaScript's `JSON.parse` would round a number past 2^53. A raw column is refused. `toWire` returns what the database reads for each data type: the `int` codec a number and the `bigint` codec a JavaScript `bigint`. The driver's library writes a `bigint` as bare digits, which MySQL reads as an exact integer beside a column or an expression; it would quote decimal text, which MySQL compares with an expression as a double, so the Postgres `int8` codec's decimal text does not fit here. Where nothing gives a parameter a type, as in `?1 + ?2` in raw SQL, the author writes the cast, as on Postgres. The bigint codec refuses a value outside the signed 64-bit range. `mysql/bigintnumber@1` reads a `bigint`, or an integral decimal such as a sum of integers, as a JavaScript number, and refuses a value outside ±(2^53 − 1) rather than round it; read without a column, as an aggregate, a computed value or a raw query's column, it cannot tell which, so its fix names `sumBigInt` and `countBigInt`, a `BigInt` field and `mysql/bigint@1` in raw SQL; it projects into JSON as text, as `bigint` does. `mysql/double@1` reads a `double`, as the text the server prints, as a number, and refuses to write `NaN` or an infinity. `mysql/decimal@1` reads decimal text as the server prints it, padded to the column's scale, projects into JSON as `CAST(x AS CHAR)`, and wraps each parameter in `CAST(?N AS DECIMAL(65,s))` through `MysqlCodecDescriptor.wrapParameter`, because both servers compare a text parameter inside `IN`, and MariaDB inside `BETWEEN`, as a double; `s` is 30, or less for a column with more than 35 digits before the point, so the cast holds every value of the column, and the codec refuses text the cast would clamp or round, saying what the column holds and what can be sent for it. A codec reference without a precision, such as a raw or prepared parameter declared as `mysql/decimal@1` alone, belongs to no column: it is cast to `DECIMAL(65,30)`, and its refusal says what can be sent and how to send a wider value: a prepared statement declares the parameter's precision and scale, and raw SQL, whose `param()` takes a codec id only, passes the value as text and writes the cast in the SQL, as in `CAST(${value} AS DECIMAL(65,0))`. A `decimal` column written without a precision or a scale records the ones the server gives it, `decimal(10,0)` or a scale of 0, in the contract's storage, with its default written as that column prints it (`src/core/mysql-database.ts`); before that, the codec checks a default against the `decimal(10,0)` the server makes. `wrapParameter` takes the parameter as an expression and the codec reference, as `projectJson` takes a column, and returns the expression the renderer writes, the parameter itself unless a codec overrides `wrappedParameter`. `mysql/boolean@1` writes 1 or 0 and reads 0 and 1 only, from a row and from an include's JSON number. `mysql/longblob@1` reads a row's bytes and, in an include, the base64 text `TO_BASE64(x)` writes, since MySQL writes a blob into JSON as `"base64:type251:…"` and MariaDB as raw bytes. `mysql/json@1` writes the document as JSON text, refuses a value that is not plain JSON, projects into JSON as `CAST(x AS CHAR)` and offers no equality or ordering. `mysql/bigintnumber@1`, `mysql/double@1` and the decimal, boolean, bytes and JSON codecs name the column of a value they cannot read or write.
- **Aggregates** (`src/core/aggregates.ts`): the overloads of `count`, `countBigInt`, `sum`, `sumBigInt`, `avg`, `min` and `max`, read off a live MySQL 8.4, with PostgreSQL's defaults: `count` and `sum` over integers read as numbers through `mysql/bigintnumber@1`, `countBigInt` and `sumBigInt` as bigints, and `avg` over an integer as `CAST(SUM(x) AS DOUBLE) / COUNT(x)`, the same in every query plan, where `AVG(x)` is cut to nine decimal places when the server groups through a temporary table. `sum` and `avg` over a `double` are a `double`; `sum` over a `decimal(p,s)` is a `decimal(min(65, p + 22), s)`, the type both servers give the total, which can need more digits than the column; a sum over a reference without a precision has no precision either. A total is exact while it fits 65 digits; a larger one, which only a column of more than 43 digits allows, may be capped to the largest value of its type, with no error or warning, whenever the server groups the rows through a temporary table, which depends on the query plan: a `groupBy` on a column without an index on both servers, and an include over several parents on MariaDB, are examples, while a `groupBy` on a column with an index is exact. There is no `avg` over a `decimal` and no `avgDecimal`, because `AVG` of a decimal is cut the same way. `sum` and `avg` over text, dates, times, booleans, bytes and JSON, and `min`/`max` over a duration, a boolean, bytes or JSON, are not offered.
- **Control tables**: `_prisma_marker` and `_prisma_ledger` live beside the application's tables, because MySQL has no schema inside a database. `src/contract-free/control-bootstrap.ts` declares their DDL.
- **Control target descriptor**: contract serializer, `contractToSchema`, `diffSchema`, the planner and the runner. `createMysqlControlTargetDescriptor` builds it from a target's descriptor meta and its facade's `migration` module, so a target that extends MySQL, such as MariaDB, reuses all of it under its own target id and session settings: its planned operations, its migration class (`MysqlMigrationBase`) and the imports of its `migration.ts` files name that target.
- **Planner** (`src/core/migrations/planner.ts`, `issue-planner.ts`): creates and drops tables, columns, indexes, unique constraints and foreign keys, with backtick-quoted DDL. Foreign keys are added after every table exists and dropped first. Dropping a foreign key also drops the index InnoDB made for it, when no other index served the key and the destination keeps no index of that name; dropping an index a foreign key of the destination uses, with no other index to take over, is refused, because the database refuses it. A change to a column's type, nullability or default, a primary key, a CHECK constraint, a required column with no default, and every statement such as a rename are refused with a conflict that says they are not yet supported by the migration planner. A name longer than 64 characters and an autoincrement column that does not lead the primary key or a unique constraint are refused with a conflict that says the database does not allow them. `migration.ts` is written as calls on `MysqlMigration` (`src/core/migrations/mysql-migration.ts`).
- **Runner** (`src/core/migrations/runner.ts`): MySQL commits each DDL statement as it runs, so the runner applies one space at a time, each operation with its pre- and postchecks, then verifies the space's schema, with the strictness the caller passes, and writes its marker and ledger entries in one transaction. Every space is verified, not only the app space, because the marker write is where a space counts as applied. The whole apply holds the marker lock (`src/core/marker-lock.ts`), a `GET_LOCK` named after the database, released on the same connection when the apply ends.

## Exports

- `./pack`: the pack ref for `defineContract` and the PSL interpreter
- `./runtime`: the runtime target descriptor, `createMysqlRuntimeTargetDescriptor({ descriptorMeta })`, which builds it for a database that extends MySQL from that database's runtime metadata, `MysqlContractSerializer` and the `now()` generators
- `./descriptor-meta-runtime`: `mysqlTargetDescriptorMetaRuntime`, MySQL's runtime metadata, the one place its target id and display name are written. The adapter, driver and facade read both from it
- `./control`: the control target descriptor, which sets the fallback `Temporal` when it is loaded, and `createMysqlControlTargetDescriptor`
- `./types`: the storage namespace class `MysqlDatabase` and `mysqlCreateNamespace`, for contract authoring without the control plane
- `./migration`: `MysqlMigration` as `Migration`, `MysqlMigrationBase` for a target that extends MySQL, the migration calls, the planner and the runner
- `./codecs`, `./codec-ids`, `./codec-types`, `./codec-descriptor`: codecs and their registry
- `./aggregates`: the aggregate descriptors the adapter contributes
- `./data-types`: data types and their PSL authoring entries
- `./contract-free`, `./ddl`, `./control-tables`: control-table DDL and the control table names
- `./marker-lock`: the marker lock, `withMarkerLock`, which the runner and the control adapter take and release
- `./default-normalizer`, `./sql-utils`, `./errors`: helpers the adapter shares
