# @internal/driver-mysql

MySQL runtime and control drivers for Prisma 8, built on the `mariadb` package (3.5.4 or later).

## Package Classification

- **Domain**: targets
- **Layer**: drivers
- **Plane**: multi-plane (shared, migration, runtime)

## Purpose

Connects the runtime and the control plane to a MySQL server and hands codecs every row value as text, bytes or null ([ADR 155](../../../../docs/architecture%20docs/adrs/ADR%20155%20-%20Driver%20Codec%20Boundary%20and%20Lowering%20Responsibilities.md)).

## Responsibilities

Each responsibility follows the Postgres driver unless it says why MySQL differs.

- **Statements** (`src/core/runtime/mysql-driver.ts`): every statement takes one round trip over the text protocol: the driver hands the SQL and its values to the package's `query(sql, values)`, or `queryStream(sql, values)` for a stream, and the package writes each value into the statement. The driver never writes a value into SQL itself and never prepares a statement. `src/core/positional-params.ts` first writes the adapter's numbered `?N` as MySQL's positional `?` and orders the values to match, a value repeated as often as its `?N` appears; a bare `?` takes the values in order. It reads the SQL with the target's lexer, so a `?` inside a quoted string, a backtick identifier or a comment stays text, and an executable `/*!` comment is refused. A statement whose placeholders and values do not match raises `RUNTIME.PARAM_PLACEHOLDER_MISMATCH`. So does a statement with values while the server reports `NO_BACKSLASH_ESCAPES` on, which only a user's raw `SET` can do (`src/core/statement.ts`, read from the status flag the package records from each reply, with no extra query): in that mode MySQL ends a string at a backslash and a quote, while the package's placeholder search reads an escaped quote, so raw SQL such as `'a\' , ?` would put a value outside its literal. A statement without values still runs, so the mode can be turned off again; the driver's own lexer keeps reading a backslash as an escape, so at worst it refuses such a statement for a `?` it reads outside a string. The package substitutes the values after this rewrite, so it never scans a value for placeholders. `multipleStatements`, named placeholders and the package's `SET` expansion of an object stay off. The request's `preparedStatementHandle` is ignored, which ADR 210 allows.
- **Values** (`src/core/parameter-values.ts`): the package writes a string quoted and escaped, a `Buffer` as `_BINARY '…'`, a number or a bigint as its digits, and `null` as `NULL`. It escapes for the session's current backslash mode, which it reads from the `NO_BACKSLASH_ESCAPES` flag in every reply from the server, and it escapes bytes for the connection's character set, utf8mb4. An integer number is written as digits, which MySQL reads as an integer, so `LIMIT ?1` takes any integer; a fractional number such as `2.5` is written as `2.5`, which MySQL reads as an exact DECIMAL, and a large or tiny one such as `1e21` as `1e+21`, which MySQL reads as a DOUBLE. So `?1 + ?2` with 0.1 and 0.2 gives `0.3`; a comparison with a FLOAT or DOUBLE column is made as a double either way. Negative zero is written as `0`. The driver refuses what the package would write wrongly: a non-finite number, which it would write as `NaN` or `Infinity`; a `bigint` outside the signed 64-bit range, so a parameter's type never depends on its value; and a `Date`, which it would write in the process's local time zone (the MySQL codecs send dates as text). A `Uint8Array` is passed as a Buffer over the same bytes, because the package writes any other `Uint8Array` as JSON text. A refused value raises `RUNTIME.ENCODE_FAILED` with `paramIndex` and `received`, and the value itself is left out. The package's `logParam` is off, so it appends no values to error messages; MySQL's own message can still quote a value, such as `Duplicate entry '…'`, as Postgres's `Key (email)=(…)` does.
- **Rows** (`src/core/text-or-bytes.ts`): both drivers return every row value in the form [ADR 155](../../../../docs/architecture%20docs/adrs/ADR%20155%20-%20Driver%20Codec%20Boundary%20and%20Lowering%20Responsibilities.md) sets: text, a `Uint8Array` or `null`. Over the text protocol MySQL sends every value as its text. One `typeCast`, `readTextOrBytes`, reads a binary-collation string or blob, BIT, GEOMETRY and any type the package has no name for, such as MySQL 9's VECTOR, as bytes, and every other column as the text MySQL wrote: a FLOAT `0.1`, a DOUBLE `1e20`, a YEAR `0000`, a ZEROFILL `TINYINT(3)` `005`, a `TIME(2)` `25:00:00.50`. A value written as `_BINARY '…'`, such as `SELECT ?1` with bytes, comes back as bytes. DECIMAL, JSON, ENUM and SET (`a,b`) arrive as MySQL's text.
- **Connection URL** (`src/core/connection-options.ts`): reads the TLS parameters as `pg-connection-string` reads them for Postgres: `ssl` (`true`, `1`, `false`, `0`), `sslmode` (`disable`; `no-verify` accepts any certificate; every other mode verifies the certificate and host name), and `sslcert`, `sslkey` and `sslrootcert`, each the path of a PEM file. It also reads `allowPublicKeyRetrieval` (off by default; MySQL 8.4's `caching_sha2_password` needs it, or TLS, over plain TCP). It ignores any other parameter, as `pg` does: the package never sees the URL, so a parameter such as `multipleStatements` has no effect. Two parameters are refused with `RUNTIME.BINDING_INVALID`, because the driver cannot do what they ask. `sslcert` without `sslkey` is refused, because in a Prisma 7 MySQL URL `sslcert` named the CA file that checks the server, which is now `sslrootcert`; the message says so. A `charset` is refused, because every connection uses utf8mb4: the driver reads each statement as utf8mb4 to find its placeholders, and MySQL must read it the same way. No error copies the URL or a parameter's value. The package never follows a server's redirect to another host (`permitRedirect: false`), as `pg` never does.
- **Pool** (`MysqlDriverCreateOptions.poolOptions`): sized and timed as the Postgres facade sizes `pg.Pool`. The pool opens a connection only when one is needed, closes one idle for `idleTimeoutMillis` (30 seconds by default), and waits `connectionTimeoutMillis` (20 seconds) both to open a connection and for a pooled one to come free; `max` (10 by default) sets its size.
- **Session**: the package runs the session setup once on each physical connection (`initSql`). It clears `NO_BACKSLASH_ESCAPES` and `ANSI_QUOTES`, so MySQL reads quoted text as the driver's lexer does, sets utf8mb4, none of which holds a value. The session settings the target declares and the stack passes to `create` (the UTC `time_zone`) are set with one `SET SESSION` (`src/core/session-settings.ts`), each value written by the package, the first time the runtime driver takes each physical connection from the pool, as the Postgres driver's `SessionSettingsGuard` sets them with `set_config($1, $2)`; the control driver sets them the same way after it connects. A value of decimal integer text is sent as a number, because MySQL refuses text for an integer variable. A setting MySQL refuses fails the statement at once with the `SqlQueryError` MySQL raised, and the connection is destroyed. There is no reset on release: a raw `SET` stays on the connection for its lifetime, as on Postgres. The pool rolls back a transaction left open on a connection it gets back.
- **Errors** (`src/core/normalize-error.ts`): as on Postgres, a lost connection (the package marks it fatal) and a pool that gives no connection in time are a `SqlConnectionError` with `transient: true`, and the lost connection is destroyed. A sign-in MySQL refuses (1045, 1698, 1524) is the `SqlQueryError` MySQL raised, as Postgres reports 28P01. A sign-in that needs the server's public key (the package's error 45044: the account uses `caching_sha2_password` or `sha256_password` and the connection has no TLS) is a `SqlConnectionError` with `transient: false` whose message names `allowPublicKeyRetrieval=true` and TLS, and session setup that fails (45030) is one too. A Node socket or DNS error is a `SqlConnectionError` classified by its code with the Postgres driver's table: a refused connection and an unknown or unreachable host are not transient; a reset, a timeout, a broken pipe and a failed DNS lookup are. The pool keeps retrying a connection until `connectionTimeoutMillis` ends, pausing longer after each failure, up to 10 seconds, and reports each failure to its `logger.error` as it happens, together with every failed statement. The driver reacts only to an error the package marks fatal that no retry can get past: a refused sign-in, a missing public key, failing session setup, a refused connection or an unknown or unreachable host; a statement can fail with a sign-in's error number, such as 1524, but not fatally. It fails the statements waiting for a connection at once, as `pg.Pool` rejects a pending connect whose connection fails, and keeps no failure, as `pg.Pool` keeps none: a later statement waits for the pool's next attempt. This is where the package differs from `pg.Pool`, which tries each connect at once. Its retries and pauses are fixed: within one attempt it retries a refused connection or an unknown host every 500 ms, and after each failed attempt it pauses 200 ms longer, up to 10 seconds. So while the server stays unreachable each later statement waits: measured, about 200 ms more for each statement after a refused sign-in, and after a refused connection at least 500 ms, growing with the pauses up to about 10 seconds. The package has no way to remove a request from its queue, so a statement the driver fails leaves its request there until the pool serves it or `connectionTimeoutMillis` ends. The driver returns a connection the pool hands to such a request straight to the pool: after 500 statements failed against a refused port, 500 requests stayed queued, and once the server accepted connections the next statement ran after 589 ms, behind them. The pool makes no attempt while no statement waits, so once the cause is fixed the next statement runs, after any pause still under way. A pool timeout caused by one of these failures reports it. Any other error MySQL reports is a `SqlQueryError` with its SQLSTATE and no `detail`, since MySQL sends none. MySQL reports every constraint violation under SQLSTATE 23000, so the driver maps a duplicate key (1062, 1586) to `23505`, a foreign key violation (1216, 1217, 1451, 1452) to `23503`, a NULL in a NOT NULL column (1048) to `23502` and a CHECK violation (3819) to `23514`, as Postgres sends them and as the SQLite driver maps its own. `DRIVER.NOT_CONNECTED` means the driver was used before `connect` or after `close`; a failed control connection is `DRIVER.CONNECTION_FAILED` with the URL redacted.
- **Runtime driver** (`./runtime`): a `mariadb` pool. A query reads its whole result and returns its connection before the first row, as the Postgres facade does without `cursor`, so a statement awaited inside the loop over a query in a transaction runs. `stream: true` streams rows as they arrive instead. Statements on a held connection or transaction reach the server in the order they are sent, under a copy of the Postgres driver's per-client lock: a statement holds its client's lock until it settles, and a stream for its whole life. A statement sent while a stream on the connection is open therefore waits for the stream to end, and one awaited inside the stream's own loop never finishes, as on Postgres with a cursor. When the caller stops a pooled stream early, the driver drops the rest if the whole result has arrived and returns the connection; otherwise it destroys the connection, so a large result is not downloaded only to be thrown away, and the package opens one short-lived extra connection to send `KILL`, because MySQL cannot cancel a statement on its own connection. A held connection reads and drops the rest, so its session survives. Releasing a held connection while a statement on it is still running, such as a stream the caller dropped, destroys it: the package's release sends `ROLLBACK` behind that statement and waits for it, which would never finish, where `pg`'s release does not wait. Transactions use the package's `beginTransaction()`, `commit()` and `rollback()`. `close()` waits for every connection and stream it has handed out, then ends the pool.
- **Control driver** (`./control`): one connection, running statements as the runtime driver does, a user's `rawSql` migration step included, and starting its session with the settings the stack passes.

## Exports

- `./runtime`: the runtime driver descriptor, and the `MysqlBinding`, `MysqlDriverCreateOptions` and `MysqlPoolOptions` types
- `./control`: the control driver descriptor and `MysqlControlDriver`
