# @internal/driver-mysql

MySQL runtime and control drivers for Prisma 8, built on the `mariadb` package (3.5.4 or later).

## Package Classification

- **Domain**: targets
- **Layer**: drivers
- **Plane**: multi-plane (shared, migration, runtime)

## Purpose

Connects the runtime and the control plane to a MySQL server and hands codecs every row value as text, bytes or null ([ADR 155](../../../../docs/architecture%20docs/adrs/ADR%20155%20-%20Driver%20Codec%20Boundary%20and%20Lowering%20Responsibilities.md)).

## Responsibilities

Each responsibility follows the Postgres driver unless it says why MySQL differs.

- **Statements** (`src/core/runtime/mysql-driver.ts`): every statement takes one round trip over the text protocol: the driver hands the SQL and its values to the package's `query(sql, values)`, or `queryStream(sql, values)` for a stream, and the package writes each value into the statement. The driver never writes a value into SQL itself and never prepares a statement. `src/core/positional-params.ts` first writes the adapter's numbered `?N` as MySQL's positional `?` and orders the values to match, a value repeated as often as its `?N` appears; a bare `?` takes the values in order. It reads the SQL with the target's lexer, which reads it as MySQL does, so a `?` inside a quoted string, a backtick identifier or a comment stays text, and an executable `/*!` comment is refused. The package then finds the placeholders again with its own, simpler search, which reads a few raw-SQL shapes differently (see [Environment requirements](#environment-requirements)). A statement whose placeholders and values do not match raises `RUNTIME.PARAM_PLACEHOLDER_MISMATCH`. A statement with values is refused with `RUNTIME.SQL_MODE_UNSUPPORTED` while the server reports `NO_BACKSLASH_ESCAPES` on, and with `RUNTIME.CHARACTER_SET_UNSUPPORTED` while the driver cannot confirm that `character_set_client` is utf8mb4 (`src/core/statement.ts`, read from the status flag and the character set the package records from each reply, with no extra query). A statement without values is handed to the package as written, with no values, so the package sends it without searching it for placeholders; it still runs in either state, so the setting can be put back. The package substitutes the values after the driver's rewrite, so it never scans a value for placeholders. `multipleStatements`, named placeholders and the package's `SET` expansion of an object stay off. The request's `preparedStatementHandle` is ignored, which ADR 210 allows.
- **Values** (`src/core/parameter-values.ts`): the package writes a string quoted and escaped, a `Buffer` as `_BINARY '…'`, a number or a bigint as its digits, and `null` as `NULL`. It escapes for the backslash mode the server reports in the `NO_BACKSLASH_ESCAPES` flag of every reply, and for the connection's character set, utf8mb4. A value stays inside its literal only while the [environment requirements](#environment-requirements) hold. An integer number is written as digits, which MySQL reads as an integer, so `LIMIT ?1` takes any integer; a fractional number such as `2.5` is written as `2.5`, which MySQL reads as an exact DECIMAL, and a large or tiny one such as `1e21` as `1e+21`, which MySQL reads as a DOUBLE. So `?1 + ?2` with 0.1 and 0.2 gives `0.3`; a comparison with a FLOAT or DOUBLE column is made as a double either way. Negative zero is written as `0`. The driver refuses what the package would write wrongly: a non-finite number, which it would write as `NaN` or `Infinity`; a `bigint` outside the signed 64-bit range, so a parameter's type never depends on its value; a `Date`, which it would write in the process's local time zone (the MySQL codecs send dates as text); and text with a lone UTF-16 surrogate, which it would store as `?` or as U+FFFD depending on the text's length. A `Uint8Array` is passed as a Buffer over the same bytes, because the package writes any other `Uint8Array` as JSON text. A refused value raises `RUNTIME.ENCODE_FAILED` with `paramIndex` and `received`, and the value itself is left out. The package's `logParam` is off, so it appends no values to error messages; MySQL's own message can still quote a value, such as `Duplicate entry '…'`, as Postgres's `Key (email)=(…)` does.
- **Rows** (`src/core/text-or-bytes.ts`): both drivers return every row value in the form [ADR 155](../../../../docs/architecture%20docs/adrs/ADR%20155%20-%20Driver%20Codec%20Boundary%20and%20Lowering%20Responsibilities.md) sets: text, a `Uint8Array` or `null`. Over the text protocol MySQL sends every value as its text. One `typeCast`, `readTextOrBytes`, reads a binary-collation string or blob, BIT, GEOMETRY and any type the package has no name for, such as MySQL 9's VECTOR, as bytes, and every other column as the text MySQL wrote: a FLOAT `0.1`, a DOUBLE `1e20`, a YEAR `0000`, a ZEROFILL `TINYINT(3)` `005`, a `TIME(2)` `25:00:00.50`. A value written as `_BINARY '…'`, such as `SELECT ?1` with bytes, comes back as bytes. DECIMAL, JSON, ENUM and SET (`a,b`) arrive as MySQL's text.
- **Connection URL** (`src/core/connection-options.ts`): reads the TLS parameters as `pg-connection-string` reads them for Postgres: `ssl` (`true`, `1`, `false`, `0`), `sslmode` (`disable`; `no-verify` accepts any certificate; every other mode verifies the certificate and host name), and `sslcert`, `sslkey` and `sslrootcert`, each the path of a PEM file. It also reads `allowPublicKeyRetrieval` (off by default; MySQL 8.4's `caching_sha2_password` needs it, or TLS, over plain TCP). It ignores any other parameter, as `pg` does: the package never sees the URL, so a parameter such as `multipleStatements` has no effect. Two parameters are refused with `RUNTIME.BINDING_INVALID`, because the driver cannot do what they ask. `sslcert` without `sslkey` is refused, because in a Prisma 7 MySQL URL `sslcert` named the CA file that checks the server, which is now `sslrootcert`; the message says so. A `charset` is refused, because every connection uses utf8mb4: the driver reads each statement as utf8mb4 to find its placeholders, and MySQL must read it the same way. No error copies the URL or a parameter's value. The package never follows a server's redirect to another host (`permitRedirect: false`), as `pg` never does.
- **Pool** (`MysqlDriverCreateOptions.poolOptions`): sized and timed as the Postgres facade sizes `pg.Pool`. The pool opens a connection only when one is needed, closes one idle for `idleTimeoutMillis` (30 seconds by default), and waits `connectionTimeoutMillis` (20 seconds) both to open a connection and for a pooled one to come free; `max` (10 by default) sets its size.
- **Session**: the package runs the session setup once on each physical connection (`initSql`). It removes `NO_BACKSLASH_ESCAPES` and `ANSI_QUOTES` from `sql_mode`, so MySQL reads quoted text as the driver's lexer and the package do, and sets utf8mb4; none of these holds a value. The [environment requirements](#environment-requirements) say what must keep them so. The session settings the target declares and the stack passes to `create` (the UTC `time_zone`) are set with one `SET SESSION` (`src/core/session-settings.ts`), each value written by the package, the first time the runtime driver takes each physical connection from the pool, as the Postgres driver's `SessionSettingsGuard` sets them with `set_config($1, $2)`; the control driver sets them the same way after it connects. A value of decimal integer text is sent as a number, because MySQL refuses text for an integer variable. A setting MySQL refuses fails the statement at once with the `SqlQueryError` MySQL raised, and the connection is destroyed. There is no reset on release: a raw `SET` stays on the connection for its lifetime, as on Postgres. The pool rolls back a transaction left open on a connection it gets back.
- **Errors** (`src/core/normalize-error.ts`): as on Postgres, a lost connection (the package marks it fatal) and a pool that gives no connection in time are a `SqlConnectionError` with `transient: true`, and the lost connection is destroyed. A sign-in MySQL refuses (1045, 1698, 1524) is the `SqlQueryError` MySQL raised, as Postgres reports 28P01. A sign-in that needs the server's public key (the package's error 45044: the account uses `caching_sha2_password` or `sha256_password` and the connection has no TLS) is a `SqlConnectionError` with `transient: false` whose message names `allowPublicKeyRetrieval=true` and TLS, and session setup that fails (45030) is one too. A Node socket or DNS error is a `SqlConnectionError` classified by its code with the Postgres driver's table: a refused connection and an unknown or unreachable host are not transient; a reset, a timeout, a broken pipe and a failed DNS lookup are. The pool keeps retrying a connection until `connectionTimeoutMillis` ends, pausing longer after each failure, up to 10 seconds, and reports each failure to its `logger.error` as it happens, together with every failed statement. The driver reacts only to an error the package marks fatal that no retry can get past: a refused sign-in, a missing public key, failing session setup, a refused connection or an unknown or unreachable host; a statement can fail with a sign-in's error number, such as 1524, but not fatally. It fails the statements waiting for a connection at once, as `pg.Pool` rejects a pending connect whose connection fails, and keeps no failure, as `pg.Pool` keeps none: a later statement waits for the pool's next attempt. This is where the package differs from `pg.Pool`, which tries each connect at once. Its retries and pauses are fixed: within one attempt it retries a refused connection or an unknown host every 500 ms, and after each failed attempt it pauses 200 ms longer, up to 10 seconds. So while the server stays unreachable each later statement waits: measured, about 200 ms more for each statement after a refused sign-in, and after a refused connection at least 500 ms, growing with the pauses up to about 10 seconds. The package has no way to remove a request from its queue, so a statement the driver fails leaves its request there until the pool serves it or `connectionTimeoutMillis` ends. The driver returns a connection the pool hands to such a request straight to the pool: after 500 statements failed against a refused port, 500 requests stayed queued, and once the server accepted connections the next statement ran after 589 ms, behind them. The pool makes no attempt while no statement waits, so once the cause is fixed the next statement runs, after any pause still under way. A pool timeout caused by one of these failures reports it. Any other error MySQL reports is a `SqlQueryError` with its SQLSTATE and no `detail`, since MySQL sends none. MySQL reports every constraint violation under SQLSTATE 23000, so the driver maps a duplicate key (1062, 1586) to `23505`, a foreign key violation (1216, 1217, 1451, 1452) to `23503`, a NULL in a NOT NULL column (1048) to `23502` and a CHECK violation (3819) to `23514`, as Postgres sends them and as the SQLite driver maps its own. `DRIVER.NOT_CONNECTED` means the driver was used before `connect` or after `close`; a failed control connection is `DRIVER.CONNECTION_FAILED` with the URL redacted.
- **Runtime driver** (`./runtime`): a `mariadb` pool. A query reads its whole result and returns its connection before the first row, as the Postgres facade does without `cursor`, so a statement awaited inside the loop over a query in a transaction runs. `stream: true` streams rows as they arrive instead. Statements on a held connection or transaction reach the server in the order they are sent, under a copy of the Postgres driver's per-client lock: a statement holds its client's lock until it settles, and a stream for its whole life. A statement sent while a stream on the connection is open therefore waits for the stream to end, and one awaited inside the stream's own loop never finishes, as on Postgres with a cursor. When the caller stops a pooled stream early, the driver drops the rest if the whole result has arrived and returns the connection; otherwise it destroys the connection, so a large result is not downloaded only to be thrown away, and the package opens one short-lived extra connection to send `KILL`, because MySQL cannot cancel a statement on its own connection. A held connection reads and drops the rest, so its session survives. Releasing a held connection while a statement on it is still running, such as a stream the caller dropped, destroys it: the package's release sends `ROLLBACK` behind that statement and waits for it, which would never finish, where `pg`'s release does not wait. Transactions use the package's `beginTransaction()`, `commit()` and `rollback()`. `close()` waits for every connection and stream it has handed out, then ends the pool.
- **Control driver** (`./control`): one connection, running statements as the runtime driver does, a user's `rawSql` migration step included, one at a time in the order sent under the runtime driver's per-client lock, and starting its session with the settings the stack passes.

## Environment requirements

The driver never writes a value into SQL. The `mariadb` package does: it writes each value into the statement as a quoted, escaped literal. A value stays inside its literal only while the database and the application meet these requirements. Prisma's own SQL meets them; raw SQL, stored procedures and triggers are the application's to keep within them.

1. **The session's `sql_mode` must not contain `NO_BACKSLASH_ESCAPES` or `ANSI_QUOTES`.** The driver removes both on every connection it opens. Raw SQL, stored procedures and triggers must not add either back. A mode set on a pooled connection stays on it until the connection closes, since the driver does not reset a connection on release.
   - With `NO_BACKSLASH_ESCAPES`, MySQL ends a string at a backslash followed by a quote, while the package reads the pair as an escaped quote when it finds the placeholders and, when MySQL reports the mode off, escapes a quote in a value with a backslash. A value can then end a literal early, and the rest of it runs as SQL. The driver refuses a statement with values while MySQL reports this mode, with `RUNTIME.SQL_MODE_UNSUPPORTED`, but MySQL can report the wrong mode: after a stored procedure that sets `sql_mode`, MySQL restores the caller's mode and still reports the mode the procedure set. If the session had the mode on and the procedure turned it off, MySQL reports it off, the driver sends the statement, and a value runs as SQL.
   - With `ANSI_QUOTES`, MySQL reads `"…"` as an identifier, in which a backslash escapes nothing, while the driver and the package read it as a string. A value can then land outside its literal and run as SQL. MySQL does not report this mode, so the driver cannot refuse it.
2. **The session's `character_set_client` and `character_set_results` must stay utf8mb4.** The driver sets both, with `character_set_connection`, through `SET NAMES` on every connection, and refuses a `charset` in the URL. Raw SQL, stored procedures and triggers must not change them, with `SET NAMES`, `SET CHARACTER SET`, `SET character_set_client` or `SET character_set_results`. A change stays on a pooled connection until it closes.
   - **`character_set_client`** is the set MySQL reads statements in. The package follows a change to it: it encodes the statement in the new set and then finds its placeholders byte by byte. In a set where the second byte of some characters is a backslash, such as `sjis`, `cp932`, `big5` or `gbk`, the package then misreads where a string in raw SQL ends, and a value can run as SQL: under `sjis`, `SELECT 'ソ' AS a, 'x?1 ' AS b, ?1 AS c` ran `CURRENT_USER()` from its value, and `許` under `big5` did the same. In any set, text the set cannot hold is replaced: under `sjis`, `SELECT ?1` with `é` returns `?`.
   - **`character_set_results`** is the set MySQL sends text back in. The package decodes every text column as utf8mb4 whatever this is, so after a change every text value read back is wrong, with no error: after `SET character_set_results = latin1`, `SELECT ?1` with `é` returned `�`. No value runs as SQL. The driver cannot refuse this: MySQL reports the change, but the package keeps only `character_set_client` from the report, and the driver runs no extra query.
   - A `SET NAMES` inside a stored procedure changes both. When the procedure returns, MySQL restores `character_set_client` and `character_set_connection` but not `character_set_results`: after a procedure ran `SET NAMES sjis`, `@@character_set_results` stayed `sjis`, and the next `SELECT 'ソ'` returned `�\` until the connection closed.
   - The driver refuses a statement with values, with `RUNTIME.CHARACTER_SET_UNSUPPORTED`, while the character set the package last recorded is not utf8mb4. The package records it from the server's greeting and then from MySQL's report of changed session variables, which includes `character_set_client` only while `session_track_system_variables` does, as MySQL's default does. With it left out, the package never sees the driver's `SET NAMES`. On a server whose default character set is utf8mb4, the package then keeps writing utf8mb4 after a raw `SET NAMES sjis` while MySQL reads `sjis`, and a plain `SELECT ?` ran a value as SQL. On a server whose default is another set, the package keeps the greeting's set, so the driver refuses every statement with values although the connection is utf8mb4. Keep `character_set_client` in `session_track_system_variables`.
3. **Raw SQL must not contain a shape the package's placeholder search reads differently from MySQL** (`splitQuery` in `lib/misc/parse.js` of `mariadb` 3.5.4). In each of the first three shapes the package can put a value where MySQL reads the inside of a string literal; the value's own opening quote ends that literal, and the rest of the value runs as SQL.
   - A placeholder (a value interpolated into raw SQL) directly followed by `'`, `"`, `` ` ``, `#`, `/*`, or a `--` that opens a comment, as in `${a}''`: after each `?` the package skips the next character without reading it. Put a space after the value.
   - A block comment that opens with `/*/`: the package ends the comment at that `/`, where MySQL reads on to the next `*/`.
   - `--` followed by DEL (0x7f): MySQL opens a comment there, and the package does not.
   - Two placeholders with nothing between them, as in `${a}${b}`: the package misses the second, and MySQL then reports a syntax error.

   A statement without values is sent as written, so these shapes do not affect it.

The driver does not check the database at startup or deploy time for these requirements.
