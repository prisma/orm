# non-ported: extensions/client

Source: `packages/client/tests/functional/extensions/client.ts`

Every test in this file exercises the Prisma Client `$extends({ client: {...} })` client-component
extension mechanism (client methods, `Prisma.getExtensionContext(this)`, `$parent`, overriding
built-in methods, Prisma type-utility usage). Prisma 8 has no `$extends` client-extension surface
(zero hits for `$extends`/`getExtensionContext`/`defineExtension`/`$parent`/`customDataProxyFetch`
across `packages/` outside node_modules/dist; `packages/3-extensions/` is database extensions, not
client extensions). The subject of each test IS the client-extension mechanism itself.

- `packages/client/tests/functional/extensions/client.ts` › `allows to extend client` — subject: a client-component extension method is callable on the extended client — non-ported (no `$extends` client-extension surface; subject is client component extension)
- `packages/client/tests/functional/extensions/client.ts` › `forwards arguments to an extension method` — subject: arguments passed to an extension method are forwarded — non-ported (no `$extends` client-extension surface; subject is client component argument forwarding)
- `packages/client/tests/functional/extensions/client.ts` › `forwards return value from  an extension method` — subject: the return value of an extension method is propagated — non-ported (no `$extends` client-extension surface; subject is client component return value propagation)
- `packages/client/tests/functional/extensions/client.ts` › `allows single extension to have multiple extension methods` — subject: a single `$extends` call can define multiple client methods — non-ported (no `$extends` client-extension surface; subject is multiple client component methods in one extension)
- `packages/client/tests/functional/extensions/client.ts` › `allows extension methods to call each other` — subject: one client extension method calls another via `Prisma.getExtensionContext(this)` — non-ported (no `$extends` client-extension surface; subject is intra-extension method invocation via getExtensionContext)
- `packages/client/tests/functional/extensions/client.ts` › `allows to have multiple client extensions with their own methods` — subject: chaining two `$extends` calls accumulates both sets of methods — non-ported (no `$extends` client-extension surface; subject is chained client extensions)
- `packages/client/tests/functional/extensions/client.ts` › `in case of name conflict, later extension wins` — subject: when two client extensions define the same method name, the later one wins — non-ported (no `$extends` client-extension surface; subject is client extension method precedence)
- `packages/client/tests/functional/extensions/client.ts` › `allows to override builtin methods` — subject: `$extends` overrides built-in client methods like `$transaction`/`$queryRaw` — non-ported (no `$extends` client-extension surface; subject is overriding built-in client methods via extensions)
- `packages/client/tests/functional/extensions/client.ts` › `allows to call builtin methods from extensions` — subject: a client extension method calls `this.$transaction(...)` — non-ported (no `$extends` client-extension surface; subject is calling built-in client methods from within an extension)
- `packages/client/tests/functional/extensions/client.ts` › `allows extension to call other extensions` — subject: a later extension calls methods from an earlier extension via `Prisma.getExtensionContext(this)` — non-ported (no `$extends` client-extension surface; subject is cross-extension invocation)
- `packages/client/tests/functional/extensions/client.ts` › `can access models` — subject: a client extension accesses model accessors (e.g. `ctx.user.findMany(...)`) — non-ported (no `$extends` client-extension surface; subject is model access from within a client extension)
- `packages/client/tests/functional/extensions/client.ts` › `empty extension does nothing` — subject: `$extends({})` and `$extends({ client: {} })` are no-ops — non-ported (no `$extends` client-extension surface; subject is no-op client extension behavior)
- `packages/client/tests/functional/extensions/client.ts` › `accepts property definition` — subject: a non-function property defined in a client extension is accessible on the extended client — non-ported (no `$extends` client-extension surface; subject is static property definition via client extension)
- `packages/client/tests/functional/extensions/client.ts` › `error in extension method` — subject: errors thrown synchronously in a client extension method propagate — non-ported (no `$extends` client-extension surface; subject is synchronous error propagation in client extensions)
- `packages/client/tests/functional/extensions/client.ts` › `error in async extension method` — subject: errors rejected asynchronously in a client extension method propagate — non-ported (no `$extends` client-extension surface; subject is asynchronous error propagation in client extensions)
- `packages/client/tests/functional/extensions/client.ts` › `error in extension method with no name` — subject: unnamed extension methods still propagate errors — non-ported (no `$extends` client-extension surface; subject is error propagation in unnamed client extensions)
- `packages/client/tests/functional/extensions/client.ts` › `custom method re-using input to augment` — subject: a client extension method reuses `Prisma.Exact`/`Prisma.Args`/`Prisma.Result` type utilities for method signatures — non-ported (no `$extends` client-extension surface; subject is Prisma type-utility usage in client extension method signatures)
- `packages/client/tests/functional/extensions/client.ts` › `raw queries can override their default output types` — subject: an extended client's `$executeRaw`/`$queryRaw`/`$executeRawUnsafe`/`$queryRawUnsafe`/`$runCommandRaw` type parameters work in batch `$transaction` — non-ported (no `$extends` client-extension surface; subject is type-overrides on raw query methods in extended clients)
- `packages/client/tests/functional/extensions/client.ts` › `an extension can also reference a previous one via parent` — subject: a later client extension calls an earlier extension's method via `ctx.$parent.someMethod(...)` — non-ported (no `$extends` client-extension surface; subject is `$parent` chaining across client extensions)
