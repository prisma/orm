# Non-ported — field-reference-string

- `packages/client/tests/functional/field-reference/string/tests.ts` › `simple equality` — findMany where string equals otherString field reference — Not yet ported; the earlier reason (no comparison between two columns) no longer holds: an ORM comparison takes another field of the same codec as its operand, as in `p.quantity.gt(p.maxQuantity)` (`ComparisonMethodFns` in `packages/3-extensions/sql-orm-client/src/types.ts`).
- `packages/client/tests/functional/field-reference/string/tests.ts` › `advanced filter` — string startsWith field reference — the ORM has no `startsWith`, and `like` takes the other field only as the whole pattern, so it cannot add the `%` that a prefix match needs (comparing two fields with `eq`, `gt` and the like is expressible)
- `packages/client/tests/functional/field-reference/string/tests.ts` › `wrong field type` — referencing an Int field for a String filter rejects with inline snapshot — the test snapshots a runtime rejection, and Prisma 8 has none to snapshot: a comparison accepts another field only when it has the same codec, so an Int field as the operand of a String comparison fails type checking instead (`ComparisonMethodFns` in `packages/3-extensions/sql-orm-client/src/types.ts`)
- `packages/client/tests/functional/field-reference/string/tests.ts` › `wrong model` — referencing a field of another model rejects with inline snapshot — the test snapshots a runtime rejection, and Prisma 8 has none to snapshot: the `where` callback's accessor holds only the fields of the model being filtered, so a field of another model cannot be named there
- `packages/client/tests/functional/field-reference/string/tests.ts` › `wrong identical model` — referencing a field of an identical-shaped model rejects with inline snapshot — the test snapshots a runtime rejection, and Prisma 8 has none to snapshot: the `where` callback's accessor holds only the fields of the model being filtered, so a field of another model cannot be named there
