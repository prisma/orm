# Non-ported — runtime-import

The suite reads the generated Prisma Client JS bundle (`generated/prisma/client/index.js`) on disk and asserts it contains specific runtime import path strings (`runtime/client`, `runtime/wasm-compiler-edge`) and Prisma codegen annotations (`/* !!! This is code generated by Prisma. Do not edit directly. !!!`, `/* eslint-disable */`, `// biome-ignore-all lint: generated file`). The subject is the Prisma codegen JS-bundle artifact — Prisma 8 emits `contract.json`/`contract.d.ts`, not a runtime JS bundle, so there is no equivalent.

- `packages/client/tests/functional/runtime-import/tests.ts` › `runtime bundles in JS client > imports correct runtime` — verifies generated `index.js` contains `runtime/client` or `runtime/wasm-compiler-edge` based on `clientMeta.runtime` — tests Prisma codegen JS-bundle content; no equivalent in Prisma 8
- `packages/client/tests/functional/runtime-import/tests.ts` › `runtime bundles in JS client > imported files have the expected annotations` — verifies generated `index.js` contains Prisma codegen header comments — tests Prisma codegen JS-bundle annotations; no equivalent in Prisma 8
