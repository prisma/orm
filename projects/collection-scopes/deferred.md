# Deferred

Items found during the project that are out of its scope. Each says what to do later and why it was not done here.

- **Two deferred-at-lowering callbacks for indexes have different shapes.** In `packages/2-sql/2-authoring/contract-ts`, `DeferredIndexExpression` carries its own `fields`, while `IndexConstraint.resolveOptions` uses the index's `fields`, and no source code produces a deferred expression any more. Later: unify them into one `resolve(columns)` that returns `{ options?, expression? }`, or remove `DeferredIndexExpression` if no extension package uses it. Not done because unifying them changes an exported authoring interface the weighted full-text index does not need.
- **The SQL family builds a wrong intermediate schema node for a `fullText` index.** `contractNamespaceToSchemaIR` in the SQL family turns a `fullText` index into an index over its columns with the definition as storage options. It is correct only because the Postgres conversion replaces the node. No other caller exists today. Later: let the family conversion take an index conversion from the target, so the target builds the node once. Not done because it changes the family's conversion interface for every target.
- **Two checks that a full-text index covers text columns.** `@@fullTextIndex` and the TypeScript `fullTextIndex` helper check the `textual` trait against the Postgres target's built-in codecs; the index type registry's `columnTraits` checks the contract's composed codec lookup at contract build. They agree today, and would disagree if an extension package added a textual codec. Later: have the two authoring surfaces rely on `columnTraits`, keeping their own message only for a better source location. Not done because nothing registers an extra textual codec today.
