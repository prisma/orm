## F02 — wire-name hashing and line breaks around `--`

### The function

`packages/2-sql/1-core/schema-ir/src/naming.ts:110-127`:

```ts
/**
 * Stabilizes an authored SQL body (index expression, partial-index predicate,
 * RLS policy predicate) for hashing: trim, and collapse runs of internal
 * whitespace to a single space.
 * ...
 * The normalizer is a stability commitment: any change re-suffixes all wire names.
 */
export function normalizeSqlBody(sql: string): string {
  return sql.replace(/\s+/g, ' ').trim();
}
```

JavaScript `\s` and `trim()` match space, tab, LF, CR, vertical tab, form feed, NBSP, U+2028, U+2029, U+FEFF and the other Unicode space separators.

### Facts that bound the rule

- Canonicalization (`packages/1-framework/1-core/framework-components/src/shared/tagged-literal.ts:74-99`) splits on `\r\n|\r|\n` and joins with `\n`, drops a blank first and last line, removes common leading spaces and tabs, turns whitespace-only lines into empty lines, and keeps trailing spaces on a line. So after slices 2 and 3, every hashed body has only `\n` line breaks, and may have extra indentation on some lines, trailing spaces, and empty lines.
- Until slice 3, TypeScript builder strings reach the hash unchanged, so they can hold `\r\n`, a lone `\r`, and indentation.
- Postgres keeps no comments in a stored expression. Introspection reads `pg_get_expr` and `pg_get_indexdef` (`packages/3-targets/6-adapters/postgres/src/core/control-adapter.ts:953-955, 1001`). A reprint holds `--` only inside a string constant or a quoted identifier. So infer's index-hash recompute already fails for an index authored with a comment, under any rule.
- Postgres ends a `--` comment at `\n` or `\r` (its scanner treats both as a newline). U+2028 does not end it.
- `renderEmbeddedSql` (design section 14.1) uses the test `text.includes('--')`. The candidates below use the same test.
- Policies run the function twice (`authoring.ts:276-279`, then `canonicalize.ts:41-42`), so a new rule must give the same output when applied to its own output. All candidates below do, checked on every example.
- Docs that describe the current rule: ADR 234 lines 98-99, 152 and 160-168 ("Normalizer stability"); ADR 243 line 91; ADR 244 line 114; `packages/2-sql/1-core/schema-ir/README.md:43` (names the helper only).

### Candidate outputs

Every candidate applies only when the body contains `--`. Otherwise it is the current function.

- **A**: split on `\n`; in each line replace runs of `\s` with one space and trim both ends; keep empty lines; join with `\n`; trim the whole.
- **A2**: as A, and drop empty lines.
- **A3**: as A2, but split on `\r\n`, `\r` or `\n`.
- **B**: replace runs of spaces and tabs (`[ \t]+`) with one space; trim the whole. Nothing else changes.

## F06 — `sql` values inside `${…}`

### How a tag receives `` sql`${a} AND x` `` (JavaScript and TypeScript facts)

- JavaScript calls the tag with a frozen template object and the substitution values as further arguments. The template object has one more element than there are values. Its `raw` array holds the source text of each part with escapes unprocessed; the array elements hold the processed ("cooked") text, which is `undefined` for a part with an invalid escape.
- Checked with Node:

| Call | `strings` | `strings.raw` | `values` |
| --- | --- | --- | --- |
| `` tag`${a} AND x` `` | `["", " AND x"]` | `["", " AND x"]` | `[a]` |
| `` tag`${a}` `` | `["", ""]` | `["", ""]` | `[a]` |
| `` tag`x AND ${a} AND ${a}` `` | `["x AND ", " AND ", ""]` | same | `[a, a]` |
| `` tag`\`quoted\` \${notInterp} ${a}\n` `` | ``["`quoted` ${notInterp} ", "\n"]`` | ``["\\`quoted\\` \\${notInterp} ", "\\n"]`` | `[a]` |

- A value arrives as the same object, not converted to a string (`got === obj` is true). Both arrays are frozen. One call site always passes the same template object.
- TypeScript 5.9.3 (`node_modules/typescript/lib/lib.es5.d.ts:621-623`):

```ts
interface TemplateStringsArray extends ReadonlyArray<string> {
    readonly raw: readonly string[];
}
```

- TypeScript checks each `${…}` against the rest parameter's element type. Checked in memory: with `...values: readonly never[]`, `` sqlNever`${owner} AND x` `` is TS2345 "Argument of type 'SqlExpression' is not assignable to parameter of type 'never'". With `...values: readonly SqlExpression[]`, `` sqlExpr`${owner} AND x` `` compiles, and a string or a number inside `${…}` is TS2345.
- The current tag builds its text with `strings.raw.join('')` (`packages/2-sql/2-authoring/contract-ts/src/sql-default-literal.ts:24`). Joining with values needs the escapes resolved on each raw part before an inner body is inserted, because an inner body is already canonical text.
- Composition and canonicalization, checked against the built `canonicalizeTaggedLiteralBody`: inserting a multi-line inner body into an indented outer template and canonicalizing the whole gives a different body from writing the same SQL in one literal. The inner body's continuation lines have no indentation, so the common indentation becomes 0 and the outer lines keep theirs.

```ts
const OWNER = sql`
  "userId" = auth.uid()
  OR is_admin()
`; // body: "\"userId\" = auth.uid()\nOR is_admin()"
sql`
  (${OWNER})
  AND deleted_at IS NULL
`; // joined then canonicalized: "  (\"userId\" = auth.uid()\nOR is_admin())\n  AND deleted_at IS NULL"
// the same SQL in one literal:   "(\"userId\" = auth.uid()\nOR is_admin())\nAND deleted_at IS NULL"
```

  For a one-line inner body, `` sql`${single} AND deleted_at IS NULL` `` gives `"\"userId\" = auth.uid() AND deleted_at IS NULL"`, as expected.
