# Target-named scalars for Postgres and SQLite

Shaped 2026-09-25, not started; spec input from the Mongo defaults, codecs and Prisma 6 source project (merged 2026-09-25 to 2026-09-27). See [`spec.md`](./spec.md) for the rename tables, the `Json` preset split, `Json` refusing non-JSON values on PostgreSQL and SQLite, the enum storage-type rule moving into the framework, the upgrade fragments and the documentation changes. The decision it applies is [ADR 257](../../docs/architecture%20docs/adrs/ADR%20257%20-%20Scalar%20types%20are%20named%20after%20the%20target%20on%20every%20surface.md).

> **Changed by the Convenience date and time types project (2026-10-22).** [ADR 279](../../docs/architecture%20docs/adrs/ADR%20279%20-%20Convenience%20types%20choose%20an%20explicit%20type%20from%20their%20arguments.md) keeps `DateTime` as a convenience type and renames the PostgreSQL date and time types itself: `Timestamptz` → `TimestamptzTemporal`, `Timestamp` → `TimestampTemporal`, `Date` → `DateTemporal`, `Time` → `TimeTemporal`, `Interval` → `IntervalParts`. The `DateTime` and `Timestamptz` rows of this spec's Postgres table, and `field.dateTime()` → `field.timestamptz()`, are superseded; ADR 279 lists the PostgreSQL explicit and convenience types.
