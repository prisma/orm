## Hand edits

All start from a collection of two documents and a plan that fills a new required `plan` (`h2` and `h4` also add a required `born DateTime`). The file declares `const usersValidator = { … }`, used by `checkDocuments(...)` and by the `collMod`.

- **Tightening the const (`h1`).** A required `nick` added to the const reached both operations in `ops.json`. `db migrate` stopped at the early check before the fill: `This validator change makes "nick" required. ... That document has no "nick"`. Documents unchanged.
- **Loosening the const (`h2`).** Unedited, the check stopped on `born`; documents unchanged. With `born` removed from `required`, the check passed, the fill and the validator applied, and the apply ended at the expected `SCHEMA_VERIFY_FAILED`. No "may no longer fit" warning here, correctly, since the loosened validator was applied and the documents fit it.
- **`collMod` deleted, check kept (`h3`).** `node migration.ts` wrote the check and the fill. `db migrate` ran the check against the const, ran the fill, and stopped at `SCHEMA_VERIFY_FAILED` with the new warning that rewritten documents may fail updates, and clear advice about hand edits. The validator was not changed; an update to a document fails, as the warning says.
- **Empty precheck in `ops.json` (`h4`).** Without a new hash: `MIGRATION.CONTRACT_SPACE_VIOLATION`. With the hash recomputed: `✘ [MIGRATION.INVALID_OPERATION_ENTRY] Operation collection.users.checkDocuments checks the documents of collection users, but has no check.` and `→ Run the migration.ts of that migration with node again, so it writes ops.json with the check.` Nothing ran.
- **Two validator changes on one collection (`h5`, `h5b`).** I added `const usersValidator2 = { ...usersValidator, … required: [..., 'nick'] }` and a second `collMod` using it after the planned one. `node migration.ts` accepted it (four operations). `db migrate` ran the check, the fill and the first `collMod`, and stopped at the second's own document check, naming `nick`. A re-run skipped the finished operations and stopped at the same place with `The failed apply changed nothing`. Problem 1 is about the first run's wording.
