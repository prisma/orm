## New problems, ranked

No data loss, no wrong advice, no plan that cannot apply. All four are unclear text, low severity.

1. **After the `db update` route for an enum swap, the next question names the temporary member names, which are gone from the source.** Reproduce (`wip/qa-pr2/qsw2`): a `db update`-only project with `enum Status { ACTIVE = "active"  ARCHIVED = "archived" }` on a scalar and a list. Change the values to `active2` and `archived2`; `db update` prints "To keep it with db update, rename member ACTIVE … to a name the enum does not have, keep its new stored value, … run `prisma db update --rename 'Status.ACTIVE:Status.<new member>'`. Then rename the member back to ACTIVE, run `prisma contract emit`, and run `prisma db update` again." Doing that with `ACTIVE_T`/`ARCHIVED_T` works. The rename back prints "Database already matches contract", because member names do not change the storage hash, so the snapshot under that hash keeps `ACTIVE_T`. The next change (the final swapped values) then asks about "Status.ACTIVE_T" and "Status.ARCHIVED_T" and offers `--rename 'Status.ACTIVE_T:Status.<new name>'`. Seen: questions about members the source no longer has. Answering `--rename Status.ACTIVE_T:Status.ACTIVE --rename Status.ARCHIVED_T:Status.ARCHIVED` finished the swap correctly. Should be: the rename back updates the stored snapshot, or the advice drops the rename-back step. The advice text came with the SQL enum work (#30849); PR 2 makes it reachable on MongoDB. Also, the first question for this swap under `db update` says "make the change in two migrations", which a project with no migrations cannot do directly; the second question gives the `db update` route.
2. **Two stop messages name things that do not match the document.** (a) Required enum value stop (`q8`): "To keep them, rename enum value "Status.ARCHIVED" to a value the enum keeps instead of removing it". Renaming onto a kept member is refused ("The value "ACTIVE" already exists in the origin enum"). The → advice says the right thing: add a new member and rename to it. Should be: "rename it to a new member" in the why too. (b) Validator check stop (`p7`): for a document with no `home` and a `null` element in `addresses`, it says "This validator change makes "addresses.line1" and "home.line1" required". The document lacks neither; the cause is the `null` element. With a document that does lack `home.line1` (`q1`) the message is right. Should be: name only what the shown document breaks, or say the list holds a non-object element.
3. **"Update validator on tasks" lists no change when only variant fields change** (`qb2`: `Bug.x`→`y`, `Epic.y`→`x`). Other validator labels list "added", "removed" or "changed". Should be: list the variant fields, or say which variants changed.
4. **The embedded model field question does not mention the temporary value.** `p3`: the value object question says "With --delete Address.street, the existing objects get a temporary value in the new required field "Address.line1"." The embedded model question (`Line.sku` to `Line.code`) does not, though `--delete Line.sku` fills `code` with `""` (`p3b`, warned after planning). Also, the interactive prompt still says "With --delete Address.street, …" where the user types `delete`.
