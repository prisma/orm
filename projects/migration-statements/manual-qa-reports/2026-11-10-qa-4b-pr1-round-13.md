## Problems, ranked

### Data loss

None found.

### Wrong advice

1. **On Postgres, the failed-cast advice now says to "replace that cast with a data transform".** `pg1`, `db migrate` after `--delete User.age` met `"abc"`: `replace that cast with a data transform that converts the values there, run node …/migration.ts, and re-run prisma db migrate`. On MongoDB this is right (`c7`): the cast is a `castField(...)` and a `dataTransform` replaces it. On Postgres the cast is the `ALTER COLUMN … TYPE int4 USING "age"::int4` in `alterColumnType`; a data transform does not change a column's type, and the fix is a `using` expression of your own (what `--convert` writes on Postgres). The README and the error reference say the same thing for both targets. The other two next actions (change the value; re-plan with `--convert`) are correct on both, and I used "change the value" to finish.

### Unclear text

2. **A failed `db update` lists planner warnings only as `warn` messages, not in the result's `plannerWarnings`.** `j4`: `db update --json` on a collection whose document holds a value the new enum rejects. The stream has `{"kind":"message","severity":"warn","text":"Field \"User.status\" gains enum \"Status\". No statement …"}`, and the result envelope (an error) has no `plannerWarnings`. A successful run (`j5`) has `plannerWarnings` in its result. The CLI README documents this ("the JSON result of a successful run lists …"), so it is as designed; an agent reading only the result of a failed run will miss the warning that explains the failure.
