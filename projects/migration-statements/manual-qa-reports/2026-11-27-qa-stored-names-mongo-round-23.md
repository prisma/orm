## Findings

### 45. On a database that permits only migrations, the refusal says no recovery remains, but one does

When the collection holds data and other databases have applied the migration, the refusal now ends "this database's change policy permits no recovery for this create". The upgrade note says the same. In `r23g` a recovery that keeps the data works under that policy: rename the collection aside by hand, run `db migrate` (which creates the collection with its options and indexes and records the migration as applied), copy the documents back, and drop the renamed collection. `migration status` then shows the migration as applied, which the `db sign` route does not. A user told that no recovery exists may drop the collection and lose its data, or stop. That is the opposite of what the text is for, on the database where the data most likely matters. Suggested fix: in place of "permits no recovery", describe this route: move the collection aside, run the command again, then copy its documents back, checking first that they pass the validator the create sets. It could be worth offering on every database, since it records a run of the migration.

### 46. After the re-run, the user cannot tell which of two documents under one `_id` is the earlier form

The comparison advice says that a document not listed may have changed after the copy: "the run copies it, and if collection measurements already holds its earlier form under the same _id, it then holds both, so delete the earlier one there yourself." In `r23a`, `r23b` and `r23c` that happened as described. But the re-run also runs the deletes (or the drop), so once both forms are in the target, the source no longer holds the newer one to compare with. The two documents differ only in the changed field, and nothing in the database says which is newer. I knew because I made the change; a user whose application made it would not, and deleting the wrong one loses the update. Suggested fix: tell the user to note the documents the query does not list, from the source, before running the command again, or to delete the earlier forms from the target before the re-run. The second needs care, because a target document with the same `_id` may have been there before the copy, as in `r23d`.
