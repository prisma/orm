## New points, below the severity bar

Neither loses data or gives advice that fails when followed.

1. **Low, wording. "Make the fields optional" is still offered when one of the fields is a discriminator.** Reproduce (`r8bk`, source `b7k`): a new discriminator `kind` beside `type`, and `Bug.severity` made required. The stop ends "Make the fields optional in the contract source, and plan it again". `kind` cannot be optional, so this step only works for `severity`. The fix for round 7 problem 3 leaves the step out only when every field is a discriminator. The `--backfill` step in the same message works. Also, the first sentence says "makes "kind" required and changes what "type" accepts" and does not name `severity`, which the change also makes required. Should be: offer the step only for the fields that are not discriminators, naming them.
2. **Low, wording, framework text.** After following "With db update, rename it in the database yourself first, then run db update" on MongoDB (`r8u1z`), `db update` asks for `--delete User.fullName` and says it "would lose the values of field "User.fullName"". The field it removes is already empty, so answering it keeps the data, but the text does not say so. On Postgres the same advice leads to no question, because `db update` reads the live schema. The text is in `packages/1-framework/3-tooling/cli/src/control-api/statements/resolve-statements.ts`.

Round 7 point 7 ("rows" in two MongoDB statement errors) is unchanged; it is framework text outside this PR (`r8q9`, `r8bx`).
