Planner hints come from the **authoring layer**: `@@hint(was: "old_name")` in PSL, or `sql({ hint: { was: 'old_name' } })` in the TypeScript DSL. They travel in `contract.json` in a top-level `hints` section that no hash covers, so adding or removing a hint never changes the storage, execution or profile hash. Every snapshot the migration tooling stores, and the destination contract the Postgres ledger records, has the section stripped. The planner reads hints from the destination contract it is given. A destination named by `--to` is a snapshot, so it carries none. An extension's own `contract.json` may carry hints, but they have no effect: the planner never runs for an extension's contract space, whose migrations are built in advance, and the snapshot store strips hints when it seeds that space.
