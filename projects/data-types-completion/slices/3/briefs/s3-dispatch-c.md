# Slice 3, dispatch c: PostgreSQL's year text and the Postgres date, time and bytes tags

Dispatch c of `projects/data-types-completion/slices/3/plan.md`. Read the slice plan, ADR 254 "Casts", "How PSL writes a value" and "Date and time types", and decisions 3, 4, 17, 18, 19 and 20 in `design-notes.md`. The map is `wip/s3/inventory-authoring.md` sections 1 to 3. TML-3396's description, quoted here, lists where the year text is converted today: read in `adaptPostgresEra` (`temporal-codec-helpers.ts`), `TIMESTAMPTZ_TEXT` (`date-codecs.ts`) and the Postgres wrapper around the shared date and time reader; written in `postgresYearText` (`standard-default-text.ts`), `encodeDate` (`date-codecs.ts`) and `storedTemporalText` (`prisma7-temporal-defaults.ts`). Some may have moved; find them all.

Today a Postgres date, time, interval or bytes default is written as a quoted string, `@default("2024-01-01")`, and read through a cast from `pg/text` that parses the text. After this dispatch each of those types has a tag, `` @default(date`2024-01-01`) ``, and the quoted string is refused with a message that shows the tag.

## Build

1. **PostgreSQL's year text.** One pair of functions in the Postgres target reads and writes PostgreSQL's year text, as ADR 254 "Date and time types" describes: a year after 9999 is written without its sign and leading zeros, a year at or before 0000 with a ` BC` suffix and PostgreSQL's year number, and the reader takes both. Every date and time codec's `fromWire` and `toWire`, including the `Temporal` codecs' `toWire` (which converts nothing today), and the tags use it; every other conversion listed above is deleted. Test with one table of dates: 4714-11-24 BC, 44 BC, 1 BC, year 1, year 9999, year 10000 and the latest value. Each row is read and written by every codec of every date and time type, and accepted by PGlite on insert and returned unchanged on select.
2. **Tags.** Register tags `date`, `time`, `timetz`, `timestamp`, `timestamptz`, `interval` and `bytea` in `postgres/src/core/data-type-entries.ts`, each under its type's id, with `parse`, `print` and `documentation`. `parse` follows ADR 254 "Date and time types" exactly: it reads ISO 8601 with a four-digit or signed six-digit year and a `T` or a space, the text PostgreSQL prints (` BC`, five- or six-digit years, `infinity` and `-infinity` where the type holds them, `IntervalStyle = postgres` interval text), uses no `Temporal` and no `Date`, and refuses each case the ADR lists with a message that names what is wrong and shows text the type takes. The `bytea` body is the hex text PostgreSQL prints, `` bytea`\x68656c6c6f` ``; the stored value stays base64. `print` writes the stored value back in the form `parse` reads. Reuse the existing readers that produce these stored forms; there must be one reader per type.
3. **Casts.** Delete the seven casts from `pg/text` built by `typeCanonicalFromText` in `postgres/src/core/data-types.ts`. Keep `toCanonicalForm` on those types for now; dispatch e deletes it. `pg/uuid`, `pg/char`, `pg/varchar`, `pg/inet`, `pg/bit`, `pg/varbit` and `postgis/geometry` keep their casts from text. A quoted string on a date, time, interval or bytes column is refused through `exactRewrite` with the tag to write; test the message for each type.
4. **`infinity`.** The `Temporal` and `Date` codecs of `pg/date`, `pg/timestamp` and `pg/timestamptz` refuse `infinity` and `-infinity` in `fromDataTypeValue` with a message that names the text codec that holds them. A `Temporal` column `@default(timestamptz`infinity`)` is refused at `contract emit` with `PSL_INVALID_DEFAULT_LITERAL`.
5. **Language server.** At a value position, completion offers only the tags whose type the receiving type is or casts from (`completion-values.ts`, `sql-attribute-specs.ts` `scalarDefaultArms`). A `DateTime @db.Date` default offers `date` and `sql`, not the other six. Update the expected-form strings in tests that list admitted forms.
6. **Rewrite every Prisma 8 schema and test that writes a quoted date, time, interval or bytes default** to the tag (inventory section 1: 18 test files and 3 fixture schemas; recheck the list, #30628 and later merges may have added some). `_fixture-before-canonical-form/contract.prisma` is deliberately old and stays as it is; the test that reads it changes to expect the refusal. Prisma 7 schemas keep their quoted strings; the Prisma 7 reader is dispatch f, so it keeps working through whatever path it has now. If the deleted casts break the Prisma 7 reader, give it the narrowest local fix that keeps today's output, and say so in the report.
