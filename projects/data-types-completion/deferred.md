# Deferred follow-ups

Found while building; not in any slice. File as Linear issues at close-out.

- `pnpm lint:deps` cannot see imports between packages: `@internal/*` imports resolve to `dist/*.mjs`, which `dependency-cruiser.config.mjs` excludes, so plane boundaries in `architecture.config.json` are not checked across packages. Found in the slice 1 system design review (F01).
- Rename the pack descriptor key `authoring.dataTypes` (PSL value entries: tags, plain entries, number classifier) so it does not share a name with `dataTypes` (the data types). Slice 3 deletes `tagEntryKey`, `isTagEntryKey`, `authoringEntryType` and `CONTRACT.DATA_TYPE_ENTRY_KEY_INVALID`, because SQLite's `json` entry moves under `sqlite/json`; the rename of the key itself stays here. Touches ADR 254 and every pack. Slice 1 system design review F10, slice 2 system design review F08. In the same rename, give `AuthoringTypeNamespace` values one noun: `postgresScalarAuthoringTypes`, `postgresNativeAuthoringTypes`, `postgresAuthoringTypes`, `sqliteAuthoringTypes` and `mongoScalarAuthoringTypes` against `postgresPslTypeConstructors` and `sqlitePslTypeConstructors`. It touches about 40 test files and ADR 257.
- `pnpm fixtures:emit` fails from a clean start when an extension's contract-space head hash changes: example emits run before `build:contract-space` and `migrations:regen`, and the extension `dist` bundles the head hash. Workaround used in slice 2: run `build:contract-space`, `migrations:regen` and an extension build first. Fix the script order.
- `test/integration/test/value-objects/` fixture config no longer emits (`PSL_NO_OPTED_IN_SCHEMA_FILES`): its schema lacks the `// use prisma-8` directive that #30379 started requiring on 2026-09-24. Older than this project; slice 2 rewrote its committed contract with the upgrade script instead. Add the directive and re-emit.
- Slice 4 (TML-3387): a placeholder matches decimal digits only (design 2.2 rule 1), so a reported `numeric(10,-2)` is not recognised although `pg/numeric` allows a negative scale since TML-3278. The resolver's placeholder pattern must accept an optional leading minus for parameters whose schema allows negatives. Add to the slice 3 plan.
- `buildReadAggregate`, used by read-only commands such as `migration status`, falls back to a placeholder contract when `contract.json` does not deserialize, so those commands do not report an old-format contract. Older than this project; found in slice 2 review fixes round 1.
- ADR 204's "At a glance" interface still lists `validateContract` and `schemaVerify`, which no longer exist.
- The SQLite busy timeout (5000 ms) is written in both the runtime and the control driver; one shared constant would keep them equal.
- pgvector's pack metadata declares `types.operationTypes`, which no framework type defines and nothing reads; contract enrichment still copies it so committed contracts do not change. Delete it from the pack and from `CONTRACT_TYPES_KEYS` in `contract-enrichment.ts`, and regenerate the pgvector contracts (no hash changes; `extensions` is outside every hash). Then type `CONTRACT_TYPES_KEYS` as keys of the framework's `ComponentMetadata['types']`, so a key added there fails to compile instead of silently staying out of contracts. Found in slice 2 review fixes round 2 and the round 3 system design review.
- Both families' `signSpaces` repeat one per-space marker algorithm: read the marker, compare it with `expected`, insert it or update it with a compare-and-swap, and read it again when the compare-and-swap loses (`packages/2-sql/9-family/src/core/control-instance.ts`, `packages/2-mongo-family/9-family/src/core/control-instance.ts`). Move it into one framework function over the family's marker operations, used by both. Found in slice 2 system design reviews, rounds 1 and 2.
- `dataType` names three things: a data type id on stored columns, on the Postgres `DefaultColumn` and in `DefaultRenderer`'s third argument; a `DataType` object on `SqlColumnIR`; and the reported type text on a Postgres introspection row (`native-type-normalizer.ts`). A merge resolution in slice 2 wrote an id where the schema IR expects the database's text. Owner: slice 4 reconsiders the names when it implements design 12.1.
- An enum member written as a number that no cast admits falls back to the parsed number, as on `main`: `@@type("pg/jsonb@1") A = 9007199254740993` stores `9007199254740992` (`enum-block-members.ts`). Owner: slice 5, when enum members move under the cast rule (design 14.6).
- Release assembly: keep the cross-references between `contract-stores-data-type` and the `nullable-scalar-lists` changes (`refresh-historical-list-contracts`, `reemit-extension-list-contracts`). Owner: whoever assembles the release that ships both.
- The Postgres DDL walker behind `lowerToExecuteRequest` reads a column's rendered type text through `pgIsTextLikeNativeType` and `SERIAL_FAMILY_TYPES` (`packages/3-targets/6-adapters/postgres/src/core/control-adapter.ts`). It could read the column's data type where `DdlColumn.codecRef` is present. It cannot for a hand-written column in a `migration.ts` file (`col(name, type, options)`), which may have no `codecRef`, and `SERIAL`, `BIGSERIAL` and `SMALLSERIAL` are pseudo-types no data type declares. So the two tables stay, and the slice 4 grep check does not name them.
- Slice 4 (TML-3387), with design 12.1's change to how the DDL builders use `SqlTypeLookups`: the pair of codec lookup and data type lookup has three shapes, `SqlTypeLookups` (`packages/2-sql/1-core/contract/src/sql-data-type.ts`), `MongoTypeLookups` (`packages/2-mongo-family/1-foundation/mongo-contract/src/mongo-data-type.ts`) and a local `TypeLookups` in `packages/2-sql/2-authoring/contract-ts/src/build-contract.ts`, and slice 2 passes it as two loose fields in `storedValueReader` and `readStoredValue` (`packages/2-sql/2-authoring/contract-psl/src/data-type-default.ts`) and `ValueObjectDefaultInput` (`packages/2-sql/2-authoring/contract-psl/src/value-object-default.ts`). The three types are identical, so one framework type is their home, and those inputs take it.
- Three places use a stored value as a database value with no codec: enum CHECK constraint literals (`packages/2-sql/2-authoring/contract-ts/src/build-contract.ts`, `checkMemberValues`, rendered by `packages/3-targets/3-targets/postgres/src/core/check-expressions.ts`), Mongo `$jsonSchema` enums (`packages/2-mongo-family/2-authoring/contract-psl/src/derive-json-schema.ts`, wrong for `int64`, date or ObjectId members), and discriminator values (`packages/3-extensions/sql-orm-client/src/collection-runtime.ts`). Owner: slice 5, with enum member values. Found by the slice 3 codec inventory.
- PostGIS's `pg/geometry@1` JSON projection is `CAST(x AS text)` since slice 3 dispatch b, so an include carries the HEXEWKB text `fromWire` reads. No test runs it against a PostGIS database, because the repository's PGlite has no `postgis` extension. Add a conformance file in `packages/3-extensions/postgis/test/` through `@internal/postgres-codec-testkit`, as pgvector's, once a PostGIS database can run in tests. Related to TML-3105.
- Slice 4 (TML-3387): a `DataTypeValue` carries its parameters as written, so values of `numeric(10)` and `numeric(10,0)` compare unequal. When slice 4 adds parameter normal forms (design 12.1), `fromContract` and `withParams` store the normal form. Found in slice 3 dispatch a.
- The SQLite runtime driver does not ask `node:sqlite` for bigints, so an ordinary row of a `sqlite/bigint@1` column holding an integer past 2^53 fails to read, while an include of the column reads it through the projection's decimal text. The SQLite codec test kit reports those cases as `row-execution`, except -2^63, which `node:sqlite` on some platforms (CI's Linux) returns as a number instead of refusing, and which `fromWire` then refuses as a number outside the safe integer range (`row-from-wire-rejects`). Read integers as bigints where a codec needs them, or cast the column to text in the row's projection, as the aggregates do.
- The Supabase extension's committed `contract.prisma` is stale on `main`: `contract:generate` writes `TimestamptzString` and `TimestampString` where the committed file has `Timestamptz` and `Timestamp` (since #30553), the script's alias table still keys on `Timestamp`, and relation `index:` arguments now name the index. Regenerate it and fix the alias table. Found by TML-3582's dispatch c review; not caused by it.
- A Prisma 7 `DateTime` default on a `time` column that rounds up to midnight is refused with a suggestion of the next day's `00:00:00`, where PostgreSQL stores `24:00:00`. Found in slice 3 dispatch f review fixes.
- The foundation layer's enum accessor (`createEnumAccessor`) copies the codec interface with `unknown`, because the foundation layer cannot import framework-components. Moving it changes the public `@prisma/orm-*/contract/enum-accessor` path. Members are read with no parameters, which is right: an enum whose type needs parameters is refused. Branch review finding, deferred from slice 3.
- A number in a SQLite `DateTime` column is read as milliseconds since 1970, as before slice 3. A row written by SQLite's `unixepoch()` or `strftime('%s')` (seconds) or `julianday()` reads as a date in January 1970 instead of being refused. Prisma never writes these. Found in the slice 3 branch review.
