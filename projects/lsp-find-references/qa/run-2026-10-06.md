**Reproduction:**

**Notes:** The provider iterates `ProjectArtifacts.documents()`, which follows `inputs.uris()`; that set comes from `expandContractInputs` in `@internal/config-loader` (`language-server/src/schema-inputs.ts:31`), the same expansion `contract emit` uses, and it yields paths in sorted order here. So the provider does what the spec describes for the order the project itself has; only the phrase "input order" reads as "config order". The LSP specification does not define an order for `textDocument/references`, and editors group results by file. The server test "returns references from project files that are not open, in input order" uses `a.prisma` and `b.prisma`, which cannot tell the two orders apart.
