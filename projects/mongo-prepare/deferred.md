# Deferred

- **The MongoDB query builder does not encode literal values.** `f._id.eq('65f…')` sends a string, and no codec runs. Prepared values are encoded with their declared codec, so the same query encodes differently when prepared. Follow-up: encode query-builder literals with the field's codec. Found while designing `prepare` (spec D4).
- **A Postgres client type-checks as a prepared target but fails at run time.** `PreparedStatement.query(target, …)` types `target` as `RuntimeScope { query; execute }`. The `postgres()` client has both methods, so `ps.query(db, params)` compiles, then throws the "missing the prepared statement query bridge" invariant. Either the type should refuse the client, or clients should become targets on every family. Found by the design review of MongoDB `prepare` (spec D7).
- **The MongoDB declaration types copy SQL's.** `MongoDeclaration`, `MongoParamsFromDeclaration` and the placeholder types have the same shape as SQL's `Declaration`, `ParamsFromDeclaration` and `BindSiteParams`. A shared version would live in the framework domain, which this project may not change. Found by the drive code review of slice 1.
- **SQL `prepare` does not check placeholders against the declaration.** A `PreparedParamRef` built by hand or taken from another `prepare` call passes, and binds with its own codec. MongoDB refuses it with `RUNTIME.PREPARE_UNDECLARED_PARAM`. Found by an automated review of MongoDB `prepare`.
- **Two run-time messages do not fit an ORM read.** A bad `offset` value at run time says "skip must be a non-negative integer", using the pipeline stage's name and not the ORM method's, and neither it nor the `limit` message shows the value received. `first()` with a declared `limit` placeholder fails with the general unused-parameter message, which does not say that `first()` sets the limit to 1. Both messages come from the runtime, which does not know the ORM built the plan. Found by manual QA of prepared ORM reads.
- **`select()` does not narrow the row type in the MongoDB ORM.** `select('name')` returns rows holding only `name`, but the row type still has every field, for ad-hoc and prepared reads alike. Found by manual QA of prepared ORM reads.
