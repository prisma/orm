# A `__proto__` key in a generated `migration.ts`

## `migration-ts-proto-key-computed`

A plan can hold a value with a `__proto__` key, for example a JSON column default. The previous release wrote that key into `migration.ts` as `__proto__:`, with or without quotes. In an object literal JavaScript reads that as the prototype of the object, not as a key. Applying the planned migration worked, because `migration plan` writes `ops.json` itself. Running `migration.ts` to regenerate `ops.json` did not: for a JSON default it failed with `CONTRACT.DEFAULT_INVALID`.

`migration plan` now writes the key as `['__proto__']:`, and a newly planned migration needs no edit. A `migration.ts` that an earlier release generated does not change by itself. In each file the detection matches, rewrite the key before you run the file again:

```ts
// before
lit({ __proto__: { x: 1 }, a: 2 })
// after
lit({ ['__proto__']: { x: 1 }, a: 2 })
```
